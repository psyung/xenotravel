# XenoTravel

가볍고 웹 친화적인 해외여행 일정 플래너. 첫 버전은 **혼자 쓰는 버전**이며, 여행은 이 브라우저(localStorage)에만 저장된다.

## 실행

```bash
npm start        # http://localhost:5173
npm test         # 모델·링크 파서·동선·공유 링크 단위 테스트
```

빌드 과정과 설치할 패키지가 없다. Node 20 이상만 있으면 된다.

## 기능

- 메인 페이지 (`#/`): 바로 쓰는 새 여행 입력(여행지 · 가는 날 · 오는 날, 많이 가는 곳 칩), 내 여행 카드(다가오는 순, 다녀온 여행은 흐리게), 도시별 요즘 뜨는 곳, 기능 소개. 로고를 누르면 메인으로 온다.
  - 여행 안에서는 로고 옆에 지금 보고 있는 여행 이름이 보이고, 누르면 다른 여행으로 바꾼다 (보던 탭 그대로: 가계부 → 그 여행의 가계부). 메인에서는 일정·가계부·체크 탭을 숨긴다 (어느 여행인지 모호하므로 카드로 들어간다).
  - 주소: `#/trip/<id>`(일정), `#/trip/<id>/budget`(가계부), `#/trip/<id>/check`(체크). 새로고침해도 그 화면이 유지되고 뒤로 가기가 된다.
- 여행 만들기: 여행지, 날짜를 넣으면 날짜 수만큼 일차(Day)가 생긴다.
- 장소 추가 (해외 어디든)
  - 검색: OpenStreetMap 기반 Photon API, 지도 중심 근처 결과 우선 (입력하는 대로 검색)
  - 한국어 검색: 한글이 들어가면 Enter를 눌렀을 때 Nominatim으로 찾는다 (지도 주변 ±50km 먼저, 없으면 전체). Photon은 "도톤보리"를 못 찾고 서울의 "오사카○○" 식당을 돌려주기 때문이다. Nominatim 정책상 자동완성은 안 되고 요청 간격을 1초 이상 둔다.
    - 오사카성, 이치란 도톤보리점, 글리코 사인처럼 OSM에 한국어 이름이 있는 곳은 찾지만, 구로몬시장·USJ처럼 없는 곳은 영어 검색이나 구글맵 링크로 넣어야 한다.
  - 새 여행의 여행지 좌표도 Nominatim으로 찾는다. 예전에 서울로 잘못 저장된 여행은 여행지 이름이 트렌드 도시면 자동으로 고친다.
- 장소 종류: 관광 · 맛집 · 카페 · 쇼핑 · 기타 (카드 이름 옆 작은 색 글자)
  - 검색 결과의 OSM 태그(예: amenity/restaurant)와 트렌드 분류로 자동으로 붙고, 장소 편집 창에서 바꿀 수 있다 (다시 누르면 해제).
  - 지도 오른쪽 위 "일차별 / 종류별"로 핀 색 기준을 바꾼다. 종류별은 트리플처럼 관광=보라, 맛집=빨강, 숙소=청록이다. 동선 선은 항상 일차 색이다.
  - 엑셀에 "종류" 열이 들어간다.
  - 링크 붙여넣기: 구글맵 장소 링크, 애플맵, OpenStreetMap, `위도, 경도`
    - 구글맵 짧은 링크(`maps.app.goo.gl`)는 브라우저 보안 정책(CORS) 때문에 열 수 없어서 안내 문구를 보여준다.
  - 지도에서 직접 찍기
- 보기 방식 토글
  - 목록: 일차가 위아래로 쌓이고, 일차마다 시간 축 타임라인(시간 · 점 · 카드)으로 보인다. 위쪽 날짜 칩(Day 1, Day 2 …)을 누르면 그날로 이동하고 지도도 그날만 강조한다. ←→ 키로도 날짜를 바꾼다.
  - 보드형: 트렐로처럼 `요즘 뜨는 곳 → 장소 보관함 → Day 1 …` 칸이 가로로 놓이고, 카드를 끌어 옮긴다. 지도는 숨길 수 있다.
- 요즘 뜨는 곳 (트렌드): 여행지와 가장 가까운 도시의 신규 오픈·기간 한정 장소를 카드로 보여준다. 카드를 끌거나 "+ 담기"를 누르면 요약과 출처 링크가 함께 일정에 들어간다. 지도에는 ★로 표시된다.
- 숙소: "추가할 곳"에서 🏨 숙소로 추가를 고르고 체크인 일차와 박 수(기본 2박)를 정하면, 그 기간의 Day마다 출발·귀가 숙소로 들어간다.
  - 출발 = 전날 밤 숙소, 귀가 = 그날 밤 숙소. 숙소를 옮기는 날은 "출발 A(체크아웃) → 귀가 B(체크인)"로 보인다.
  - 첫날 출발과 마지막 날 귀가는 인접한 숙소로 채운다. 중간에 숙소가 빈 밤은 비워 두고, 그날 카드의 "+ 숙소"로 채운다.
  - 지도의 동선은 출발 숙소 → 장소들 → 귀가 숙소 순서로 이어진다. 엑셀과 PDF에도 포함된다.
- 항공편: 상단 "항공편"에서 출국·여행 중 이동·귀국편을 입력한다(편명, 공항, 현지 출발·도착 시각, 예약번호, 메모).
  - 출국·이동편은 그날 맨 위, 귀국편은 맨 아래에 표시된다. 밤 비행기는 출발일과 도착일 양쪽에 보인다.
  - 첫날 출국편이 있으면 출발 숙소를, 마지막 날 귀국편이 있으면 귀가 숙소를 자동으로 채우지 않는다.
  - 자동 조회(편명으로 시간 채우기)는 유료 항공 API가 필요해 아직 없다.
- 장소 보관함: 일정 목록 아래(화면 아래쪽)에 고정되어 일정이 길어도 항상 보인다. 카드의 "보낼 날"로 끌지 않고 원하는 날로 보낼 수 있고, 장소 편집 창에서도 다른 날로 옮길 수 있다.
- 모달(내 여행·항공편)은 바깥을 클릭하면 닫힌다.
- 지도 우클릭(모바일은 길게 누르기): "이 위치 추가" 창에서 일정에 추가하거나 숙소로 추가한다.
- 장소 카드 복제(⧉): 원본 바로 아래에 같은 카드를 만든다. 끌어서 다른 날로 옮기면 된다.
- 장소 사이 거리와 길찾기: 카드 위에 앞 장소(또는 출발 숙소)에서 오는 거리가 나온다. 1.2km 이하는 "도보 약 N분", 그보다 멀면 거리만 보인다. 누르면 구글맵 길찾기(도보/대중교통)가 열린다.
  - 직선거리로 계산한 어림값이다 (실제 길은 25% 더 길다고 보고 시속 4.5km로 걷는 걸로 계산).
  - 예상 걸음 수: 걸어갈 만한 구간(1.2km 이하)마다 보폭 0.7m로 계산해 100걸음 단위로 보여준다. 구간 · 하루 · 여행 전체 합계가 있다. 대중교통 구간과 관광지 안에서 걷는 건 빠져 있어 실제보다 적게 나온다.
  - 일차 카드의 "길찾기": 그날 전체 동선(숙소 → 장소들 → 숙소)을 구글맵 길찾기로 연다. 구글맵 URL 제한 때문에 경유지가 9곳을 넘으면 버튼이 나오지 않는다.
- 공유 링크 (상단 "공유"): 받는 사람은 앱 설치나 가입 없이 브라우저에서 보기 전용으로 본다. "내 여행으로 저장"을 누르면 사본이 생겨서 고칠 수 있다.
  - "메시지 복사"는 `제목 / 날짜 · N박 M일 · 장소 N곳 / 링크` 형태의 메시지를 복사한다.
  - 짧은 링크 `/s/<8자>`: 일정을 압축한 코드를 서버(`server.js`)가 `SHARE_DIR`(기본 `data/shares/`, git 제외)에 파일로 저장한다. 이 페이지에는 제목·요약·`og.png`가 미리보기 태그로 들어가서 카톡에서 카드로 보인다.
  - 서버 없이 정적 호스팅만 할 때는 일정 전체를 압축해서 URL `#s=` 뒤에 담은 긴 링크로 대신한다 (장소 40곳 기준 약 1,700자).
  - **`localhost` 링크는 내 PC에서만 열린다.** 친구에게 보내려면 공개 주소에 배포해야 하고, 짧은 링크를 쓰려면 디스크가 유지되는 곳이어야 한다.
  - 생성 제한: IP당 시간당 30개, 코드 200KB.
  - 링크는 만든 시점의 사본이라 이후에 고친 내용은 반영되지 않는다. 실시간 공동 편집은 다음 단계다.
  - 받은 데이터는 검증한 뒤 id를 새로 만들고, 링크 칸은 http(s)만 열린다.
- 끌어서 순서·날짜 변경, 장소 보관함(날짜 미정), 시간·메모·링크 입력, 시간순 정렬
- 동선 정리 (일차 카드 "동선 정리"): 출발 숙소 → 장소들 → 귀가 숙소의 직선거리 합이 가장 짧은 순서를 제안한다. 시간을 정한 장소는 그 자리에 고정한다. 미리 보기(카드 안 목록 + 지도 실선) → "이 순서로 바꾸기" → "되돌리기". 옮길 장소가 12곳 이하면 모든 경우를 비교하고, 더 많으면 근사 계산한다.
- 일차별 날씨 (Open-Meteo, 키 없음): 오늘부터 16일 안은 예보("흐림 17° / 3° 비 21%"), 비 올 확률이 높으면 "실내 장소 위주로" 안내. 그보다 먼 날은 "예보 전 · 12/15부터"만 보이고, 누르면 작년 같은 날 기록을 참고로 보여준다. 위치는 그날 숙소(없으면 첫 장소, 여행지). 예보는 3시간, 기록은 30일 동안 저장해서 오프라인에서도 보인다.
- 카톡용 복사 (일차 카드): 그날 일정(항공, 숙소, 시간, 장소, 메모 첫 줄, 동선 지도 링크)을 메신저에 붙일 글로 복사한다. 동행이 앱 없이 그날 계획을 본다.
- 여행 당일 "오늘" 카드: 여행 기간 중에만 맨 위에 보인다. 다음 장소(지금 이후 첫 시간) 표시, 장소마다 "주소" 복사(택시 기사에게 보여주기)와 "길찾기"(지금 위치에서), 오늘 밤 숙소 주소와 "숙소로 가기", "지출 적기", "카톡으로 오늘 일정 보내기".
- 날짜 고르기: 브라우저 기본 달력 대신 Cally 기간 달력 (PC는 두 달, 모바일은 아래에서 올라오는 시트). 항공편은 날짜 + 시간 칸.
- 오프라인 (PWA): 서비스 워커(`public/sw.js`)가 앱 파일과 CDN 라이브러리를 저장해서, 인터넷 없이 새로 열어도 일정·오늘 카드·가계부·체크리스트를 쓴다. "홈 화면에 추가"로 앱처럼 연다. 인터넷이 끊기면 위에 한 줄로 알린다.
  - 오프라인에서 안 되는 것: 지도 바탕(타일, 이용 조건 확인 전이라 저장하지 않음), 장소 검색, 길찾기, 새 날씨, 공유 링크 만들기.
  - 우리 파일은 인터넷이 되면 항상 새로 받는다(개발 중 수정이 바로 보인다). 앱 파일을 추가하면 `sw.js`의 `APP_FILES`에도 넣는다 (빠지면 `npm test`가 알려 준다).
  - 환율을 모르는 상태(오프라인)에서도 현지 돈으로 지출을 적을 수 있다. 원화는 "환율 미정"으로 두고, 환율을 받거나 직접 넣으면(인터넷이 돌아오면 자동) 채운다.
- 지도: 일차별 색상과 번호, 동선 선. 일차 제목을 누르면 그날만 강조한다.
- 여행 요약 (맨 위 카드): 출발까지 D-day, 기간, 들를 곳 수, 전체 이동 거리(직선), 예상 걸음, 항공편 노선(누르면 수정), 확인할 것(숙소가 빈 밤 등).
- 가계부 (상단 "가계부" 탭, 모바일은 아래 탭)
  - 금액을 현지 통화나 원화로 적고 분류(식비·교통·쇼핑·입장권·숙소·항공·기타)와 결제 수단을 고른다. 현지 통화는 적는 순간의 환율로 원화도 같이 저장한다.
  - 통화는 여행지 이름으로 추측하고(오사카 → 엔) 바꿀 수 있다. 환율은 처음 열 때 ExchangeRate-API(키 없음, 하루 1회 갱신)에서 받아오고, 직접 고칠 수 있다.
  - 1인 예산 · 쓴 돈 · 남은 돈, 분류별 · 날짜별 · 결제 수단별 합계, CSV 내보내기.
- 체크리스트 (상단 "체크" 탭): 출발 전 할 일 · 짐 싸기 · 쇼핑 리스트. 처음 열면 기본 항목이 들어 있고 추가·삭제할 수 있다. 남은 할 일 수가 탭에 숫자로 보인다.
  - 나라별 추천 쇼핑 목록 (`public/lib/checklist.js`의 `SHOP_PICKS`, 통화로 나라를 구분): 일본 = 돈키호테 필수템 · 아카짱혼포 육아템, 중국 = 따룬파, 대만 = 까르푸, 베트남 = 롯데마트, 태국 = 빅씨.
  - 쇼핑 리스트는 비어서 시작하고, 추천 목록은 "○○ N개 담기" 버튼을 눌러야 들어간다 (빠진 것만). 예전 버전이 자동으로 채운 쇼핑 리스트는 손대지 않았으면(그대로 + 체크 없음) 열 때 비운다. 목록을 늘리려면 SHOP_PICKS에 가게 하나를 추가하면 된다.
  - 체크리스트 항목에 "+ 가격"으로 예상 가격(현지 돈/원화)을 넣으면 가계부 "예상 (체크리스트)"와 "계획 대비"(분류별 쓴 돈 vs 예상)에 자동으로 잡힌다. 쇼핑 리스트는 쇼핑, 할 일·짐은 기타로 들어간다. 예상이 예산보다 크면 맨 위 "확인"에 알린다.
  - 가격이 있는 항목을 체크하면 가계부에 실제 지출로 기록되고(여행 중이면 그날, 아니면 출발 전), 체크를 풀면 그 기록도 지운다. 가계부에서 그 기록을 지우면 체크도 풀린다.
  - 상자마다 "체크한 것 삭제", "전체 삭제". 이미 가계부에 기록된 금액은 실제로 쓴 돈이라 남긴다.
  - 가계부와 체크리스트는 이 브라우저에만 저장되고 공유 링크에는 들어가지 않는다 (백업 파일에는 포함).
- 화면 밝기: 시스템을 따르고, 상단 달 버튼으로 밝게/어둡게 고정할 수 있다.
- 내보내기 (상단 ⋯ 메뉴)
  - 엑셀(.xlsx): 일차, 날짜, 순서, 시간, 장소, 주소, 메모, 링크, 구글맵 링크
  - PDF: 일차별 지도와 일정표가 담긴 인쇄 미리보기를 연 뒤 브라우저의 "PDF로 저장"을 쓴다.
  - 백업(JSON): 다른 브라우저나 기기로 옮길 때 쓴다.

## 트렌드 데이터 (`public/data/trends.json`)

- 현재 도시: 도쿄, 오사카, 교토, 후쿠오카 (2026-11-17 웹 조사)
- 장소마다 `status`(new / event / upcoming / classic), 기간(`since`, `until`), 요약, 출처 링크를 담는다. `approx: true`는 대략적인 위치라는 뜻이다.
- 끝난 이벤트(`until`이 지난 것)는 화면에서 자동으로 빠진다.
- 갱신 방법: 같은 형식으로 파일을 고친 뒤 `npm test`를 실행해 필드·좌표를 검증한다. 7일마다 자동으로 조사하는 배치는 다음 단계다.
- 출처마다 날짜가 다를 수 있어서 방문 전 공식 사이트 확인이 필요하다.

## 알려진 한계와 다음 단계

- 지도 타일은 Esri Light Gray Canvas(어두운 화면은 Dark Gray, 키 없이 쓰고 출처 표기, 16단계까지)를 쓴다. CARTO는 2025년부터 키가 필요하고 Stadia는 배포 주소에서 키가 필요하다.
- 지도 타일(Esri)과 검색(Photon)은 무료 공개 서버다. 개인 사용은 괜찮지만 사용자가 늘면 키 기반 서비스(MapTiler, Stadia, Google Places 등)로 바꿔야 한다.
- 입력 중 검색(Photon) 결과 이름은 영어나 현지어로 나온다. 한국어 검색(Nominatim)은 Enter를 눌러야 하고, 작은 가게는 못 찾을 수 있다. 제대로 하려면 Google Places 같은 키 기반 API가 필요하다.
- 작은 가게나 맛집은 OSM 데이터에 없을 수 있다. 이럴 때는 구글맵 링크를 붙여넣는 게 가장 확실하다.
- 다음 단계: 친구와 함께 편집하기 (링크 공유와 실시간 동기화, 서버 필요)
