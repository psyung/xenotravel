# XenoTravel 아키텍처 및 다국어(I18n) 원칙

이 문서는 XenoTravel의 상태 관리, 데이터 무결성, 4개 국어(`KO`, `EN`, `ZH`, `JA`) 처리에 관한 기술 원칙을 정의합니다.

---

## 1. 단일 상태 원천(Single Source of Truth) 원칙
1. **일정 탭 활성 일차 동기화:**
   * 상단 일차 선택 컨트롤, 타임라인 스크롤/선택, 지도 롱프레스/우클릭 추가 팝업은 모두 동일한 `selectedDay` 상태를 참조해야 합니다.
   * 특정 일차가 선택된 상태에서 지도를 길게 누르면 반드시 해당 일차로 일정과 숙소가 추가되어야 합니다.
2. **2-상태 테마 동기화:**
   * 테마 토글은 `'system'` 중간 상태 없이 `effectiveTheme` (`'light' | 'dark'`)을 단일 진실 원천으로 관리합니다.
   * 버튼 클릭 시 현재 적용된 화면 테마의 정반대 값으로 즉시 전환하고 `localStorage`와 `document.documentElement.classList`를 동시에 갱신합니다.
3. **가계부 연동 멱등성(Idempotency):**
   * 체크리스트에서 예상 금액이 입력된 항목을 개별 체크하거나 `전체 체크`할 때, 이미 가계부에 반영된 항목이 중복 합산되지 않도록 고유 연동 ID 기준으로 관리합니다.

---

## 2. 4개 국어(`KO`, `EN`, `ZH`, `JA`) 로컬라이제이션 원칙
1. **UI 사전 100% 대칭성:**
   * 모든 UI 라벨, 버튼, 툴팁, 접근성 속성(`aria-label`), 빈 상태(Empty State) 문구, 확인 모달 문구는 `KO`, `EN`, `ZH`, `JA` 4개 사전에 동일한 키 구조로 존재해야 합니다.
2. **프리셋 데이터 vs 사용자 입력 데이터 분리:**
   * **내장 프리셋 데이터(기본 샘플 여행 일정, 최근 인기 장소 추천 카드 등):** 처음부터 `{ ko: string, en: string, zh: string, ja: string }` 다국어 맵으로 저장하여 언어 스위처 전환 시 이름과 설명이 즉시 번역되어 표시되어야 합니다.
   * **사용자 생성 데이터(사용자가 직접 타이핑한 장소명, 메모, 지출 항목):** 사용자가 입력한 원문 문자열을 그대로 유지하며 강제 번역하지 않습니다.
3. **다국어 레이아웃 방어 규칙:**
   * **날짜/시간/일차 배지:** `white-space: nowrap`과 `shrink-0`을 적용해 영어(`Sat, Dec 19`)나 중국어(`12月19日 周六`)가 세로로 꺾이지 않도록 보호합니다.
   * **가변 길이 액션 버튼:** 영어(`Optimize route`, `Copy for chat`)처럼 한국어보다 긴 버튼 묶음은 컨테이너 너비가 좁아질 때 줄바꿈(`flex-wrap`)을 허용해 좌측 핵심 정보를 침범하지 않게 합니다.
   * **장문 사용자 텍스트:** 띄어쓰기가 없는 일본어 장문이나 긴 URL은 `overflow-wrap: anywhere`를 적용해 `337px` 모바일 카드 밖으로 삐져나가지 않게 처리합니다.

---

## 3. 데이터 보존 및 오프라인 회복력 원칙
1. **로컬 우선 저장:** 모든 여행 데이터는 변경 즉시 `localStorage`에 안전하게 직렬화되며, JSON 백업 파일 내보내기/불러오기와 호환성을 유지해야 합니다.
2. **인앱 브라우저 대응:** 카카오톡/SNS 인앱 브라우저 접속 시 세션 휘발 위험을 안내하고 외부 기본 브라우저 전환 가이드를 상시 접근 가능하게 유지합니다.
