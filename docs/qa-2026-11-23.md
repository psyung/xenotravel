## PART B. 이슈 상세 (Codex·Claude Code 공용 작업 기준)

> 형식: **위치 / 현재 현상 / 원인 / 완료 기준**. 요청자 번호는 (#n)으로 함께 적었습니다.

### Phase 1 — P0 · 데이터와 동작 오류

#### P0-1. 여행지 좌표가 엉뚱한 나라로 잡힘 (신규 발견) [확인]
- **위치:** 홈의 새 여행 만들기 → `geocodeDestination` (`lib/geo.js` 61행), 호출부 `app.js` 3110행 부근
- **현상:** 자동완성에서 "자싱 · 중국"을 골라 만들었는데 저장된 값이 `center: 24.14, 74.95`, `country: "in"`(인도 라자스탄)이었습니다. 그 결과 다음 문제가 함께 생겼습니다.
  - 장소가 없는 날의 지도가 인도로 이동하고, 길게 누르면 "Bardal, Madhya Pradesh, India"가 나옵니다.
  - 장소 검색 결과에 "여행지에서 4548km"처럼 거리가 잘못 표시됩니다.
  - 장소가 없는 날의 날씨가 인도 기준(최고 33°C)으로 나옵니다.
- **원인:** 자동완성 목록(`DESTINATIONS`)에는 좌표가 없습니다. 그래서 한국어 "자싱"을 Nominatim에 그대로 보내고, 첫 결과를 신뢰합니다. 고른 국가와 결과 국가가 같은지도 검증하지 않습니다.
- **완료 기준**
  - 자동완성 목록의 도시는 고정 좌표와 국가 코드를 가지며, 이 값을 쓰면 지오코딩을 하지 않습니다.
  - 목록에 없는 도시는 영어 별칭과 국가 필터로 조회합니다. 결과 국가가 고른 국가와 다르면 버립니다.
  - 여행 정보 화면에 "여행지 위치"를 작은 지도로 보여 주고 다시 고를 수 있게 합니다.
  - 이미 저장된 여행은 마이그레이션 시 `center`가 담긴 장소 평균과 300km 넘게 떨어져 있으면 장소 평균으로 고칩니다.
  - 사용자의 실제 "자싱 여행" 날씨(Day 2 "소나기 24°/18°")가 자싱 좌표로 계산된 값인지 함께 확인합니다.

#### P0-2. 항공편이 Day 1 / 마지막 날에 붙지 않음 (#3) [확인]
- **위치:** `lib/model.js`의 `flightsOnDate`(706행)와 `dayStays`(575행), 홈 상단 "확인할 것" 경고
- **현상:** 출국편(OZ367, 11/22 20:45 출발)이 여행 시작일(11/23)보다 하루 앞서면 일정에 아예 안 나옵니다. 대신 "여행 기간 밖 항공편 1개는 일정에 안 보여요" 경고만 뜹니다.
- **원인:** 항공편을 종류(출국·귀국)가 아니라 날짜가 같은지로만 일차에 붙입니다.
- **완료 기준**
  - **출국편**은 날짜와 상관없이 Day 1 맨 위 카드로 보입니다. 날짜가 시작일보다 앞이면 "전날 출발" 배지를 붙입니다.
  - **귀국편**은 마지막 날 맨 아래에 보입니다. 마지막 날 다음 날 새벽 출발도 같은 위치에 붙입니다.
  - **이동편**(`move`)은 지금처럼 날짜로 붙입니다.
  - 기간 밖 날짜로 저장할 때 선택지를 줍니다: [여행 기간을 11/22까지 늘리기] [기간은 그대로, Day 1에 붙이기].
  - 출국·귀국편이 여러 개면 시간순으로 모두 보여 줍니다.
  - 항공편 시간대 표기는 "현지 시각" 원칙을 유지합니다.
  - 인쇄/PDF와 ICS 내보내기에도 같은 위치로 나와야 합니다.

#### P0-3. 체크 해제해도 가계부 지출이 남음 (#24) [확인]
- **위치:** `lib/checklist.js`의 `toggleCheck`, `app.js`의 `#page-check` change 핸들러
- **현상:** 가격이 있는 항목을 체크하면 지출이 자동 기록됩니다. 그런데 체크를 풀어도 지출이 그대로 남고, "가계부 지출은 그대로 남겼어요"라는 토스트만 뜹니다.
- **완료 기준 (정책)**
  - 체크로 **자동 생성된 지출**(`checkId` 연결)이고 금액을 사용자가 고치지 않았다면, 체크 해제 시 지출도 삭제합니다. 토스트에 [실행 취소]를 넣습니다.
  - 사용자가 "결제" 금액을 고친 지출이면 확인 창을 띄웁니다: [지출도 삭제] [체크만 해제] [취소].
  - 가계부 화면에 체크리스트에서 온 지출임을 아이콘으로 표시합니다.

#### P0-4. "전체 해제" 확인 창에 선택지가 하나뿐 (#26) [확인]
- **위치:** `app.js`의 `changeCheckGroup` → `ask({ title: '전체 해제', actions: [체크만 해제] })`
- **현상:** "연결된 지출 4건: ¥90, ¥220, ¥110, ¥123" 안내 아래에 버튼이 "체크만 해제" 하나뿐입니다. 지출도 함께 정리하는 길이 없습니다.
- **완료 기준**
  - 버튼은 [체크 해제 + 지출 4건 삭제] [체크만 해제] [취소] 세 개입니다. 기본 포커스는 P0-3 정책과 같은 쪽에 둡니다.
  - 금액을 고친 지출이 섞여 있으면 본문에 "직접 고친 지출 n건은 남깁니다"를 명시합니다.
  - 결과 토스트에 [실행 취소]를 넣습니다.
  - 4개 국어 문구를 모두 추가합니다.

#### P0-5. 가계부 "날짜별" 막대가 카드 밖으로 넘쳐 페이지 전체가 가로로 밀림 (#13, #9) [확인]
- **위치:** `#page-budget .daybars` (`.grid2 > .box`)
- **현상:** 20일 여행에서 페이지 폭이 337px일 때 524px, 480px일 때 527px로 늘어납니다. 모바일 하단 탭 버튼(`.pg.trip-only`)이 화면 밖으로 밀리고, D13 이후는 카드 밖으로 넘칩니다. 4개 국어 모두 같습니다.
- **완료 기준**
  - 막대 차트는 카드 폭을 절대 넘지 않습니다.
  - 일수가 많으면 막대 폭을 줄이고, 라벨은 n일 간격으로만 표시합니다. 또는 카드 안에서만 가로 스크롤되게 하고 양끝을 페이드 처리합니다(결정 필요).
  - 30일 이상이면 주 단위로 묶어 보여 줍니다.
  - 모든 페이지가 320~767px에서 scrollWidth와 clientWidth가 같아야 합니다.

#### P0-6. 새 여행 모달이 좌측 하단에 붙고 아래가 잘림 (#8) [확인]
- **위치:** `#new-trip-modal` (dialog)
- **현상:** 865px 폭에서 모달이 `position: fixed; margin: 774px 0 0; left: 0; width: 520px`로 잡힙니다. 그래서 화면 왼쪽 아래에 반쯤 걸치고, 아래쪽(높이 244px 중 일부)은 화면 밖으로 잘립니다. 모바일용 바텀시트 규칙에 데스크톱 폭(520px)이 섞여 있는 상태입니다.
- **완료 기준**
  - 600px 이상: 화면 중앙 모달(최대 폭 560px), 입력칸과 날짜 버튼이 한 줄에 잘리지 않습니다.
  - 600px 미만: 폭 100% 바텀시트, `100dvh`와 safe-area를 반영합니다.
  - 항공편·공유·보관함 가져오기 등 모든 dialog가 같은 Modal/Sheet 컴포넌트를 씁니다.
  - 항공편 모달의 날짜 버튼("11/22 …")처럼 2열 칸에서 날짜가 말줄임되지 않아야 합니다.

#### P0-7. 브라우저 언어를 따르지 않고 항상 한국어로 시작 (#11) [확인]
- **위치:** `lib/i18n.js`의 `loadLang`(저장값이 없으면 `'ko'`), `index.html`의 첫 화면 스크립트
- **완료 기준**
  - 저장된 언어가 없을 때만 `navigator.languages`를 앞에서부터 확인합니다.
    - `ko*` → 한국어
    - `ja*` → 일본어
    - `zh`, `zh-CN`, `zh-SG`, `zh-Hans*` → 중국어 간체
    - `zh-TW`, `zh-HK`, `zh-Hant*` → 중국어 간체로 표시(번체 지원 전까지)
    - `en*` → 영어
    - 그 밖의 언어 → 영어(결정 필요: 영어 vs 한국어)
  - 사용자가 언어 버튼을 직접 누른 경우에만 localStorage에 저장합니다.
  - `index.html`의 첫 화면 스크립트도 같은 규칙으로 `<html lang>`을 정해, 첫 화면부터 깜빡임 없이 맞는 언어로 보이게 합니다.
  - 공유 링크(읽기 전용)도 보는 사람의 언어를 따릅니다.

#### P0-8. 여행 페이지의 "요즘 뜨는 곳"이 다른 도시를 보여 줌 (#15) [확인]
- **위치:** 일정 화면의 "요즘 뜨는 곳" 카드와 `도시 선택` select. 데이터는 `data/trends.json`(도쿄·오사카·교토·후쿠오카 4개 도시뿐)
- **현상:** 자싱 여행인데 "도시 선택"에 도쿄·오사카·교토·후쿠오카가 나오고, "지금은 도쿄·오사카·교토·후쿠오카만 있어요"라는 안내가 뜹니다.
- **완료 기준**
  - 여행 페이지에서는 **도시 선택 UI를 없앱니다.** 여행지 도시 데이터만 씁니다.
  - 여행지 데이터가 없으면 섹션 전체를 숨깁니다. 대안: 접힌 한 줄로 "이 도시 추천은 준비 중 · 장소 검색하기" CTA만 둡니다(결정 필요).
  - 도시 고르기는 홈 화면에서만 남깁니다.

#### P0-9. 숙소 날짜를 여행 시작일 전(11/22)으로 잡을 수 없음 (#2 추가 설명) [확인]
- **위치**
  - 숙소 추가 옵션: `setStayCalendar` (`app.js` 1417행)
  - 숙소 수정 에디터: `app.js` 1482~1486행
  - 여행 날짜 변경: `onDatesChange`, `M.setTripDates` (`lib/model.js`)
- **현상(재현)**
  - 여행 시작일이 11/23인 여행에서 숙소 달력을 열면 11/22 이전이 회색(선택 불가)이고, 이전 달 화살표도 막혀 있습니다.
  - 사용자가 받은 화면의 여행은 **11/23(월) – 12/12(토)**로 저장되어 있습니다. 출국편은 11/22 밤에 도착하므로 첫 숙박이 11/22부터인데, 이 숙박을 넣을 방법이 없습니다.
- **원인 1:** 숙소 체크인 min이 `Day 1 날짜`로 고정되어 있습니다(`inEl.min = dateAtIndex(trip, 0)`). 숙소는 `startIndex`(일차 번호)로만 저장되므로 여행 기간 밖 날짜를 표현할 수 없습니다. 기준이 "오늘"이 아니라 "여행 시작일"이라서, 사용자에게는 지난 날짜가 막힌 것처럼 보였습니다.
- **원인 2(데이터 손상 위험):** 여행 시작일을 11/23에서 11/22로 앞당기면 `setTripDates`가 **일차 순서를 유지하고 날짜만 다시 매깁니다.** 그래서 다음 데이터가 모두 하루씩 앞으로 밀립니다.
  - 11/23에 넣어 둔 장소가 11/22로 이동
  - 숙소의 `startIndex`
  - 지출의 `day`
  - 확인 창에 "날짜만 바뀌어요"라는 문구가 있지만, 날짜를 그대로 두는 선택지는 없습니다.
- **완료 기준**
  - 숙소 달력에서 여행 기간 밖 날짜도 고를 수 있게 합니다. 바깥 날짜는 흐리게 표시하되 비활성으로 막지 않습니다.
  - 기간 밖 날짜를 고르면 확인 창을 띄웁니다: "여행을 11/22부터로 늘릴까요? 기존 일정은 날짜 그대로 유지돼요" [늘리고 저장] [취소].
  - 여행 날짜 변경에 **"날짜 기준 유지"를 기본값**으로 추가합니다. 시작일을 k일 앞당기면 다음처럼 처리하고, 장소는 원래 날짜에 그대로 둡니다.
    - 앞에 빈 날 k개를 추가합니다.
    - 숙소 `startIndex`와 지출 `day`를 +k 합니다.
    - 시작일을 늦추면 반대로 처리하고, 잘려 나가는 날의 장소는 보관함으로 보냅니다.
  - 기존 "일차 기준 유지(모두 같이 밀기)"는 두 번째 선택지로 남깁니다.

  - "카드"를 **신용카드**와 **체크카드**로 나눕니다. 기존 `card` 값은 신용카드로 보고 마이그레이션합니다.
  - **간편결제**(Alipay, WeChat Pay, Apple Pay 등)를 추가합니다. 중국 여행은 실제로 간편결제 비중이 커서 이 항목이 없으면 기록이 어긋납니다.
  - 결제 수단 차트, CSV/엑셀 내보내기, 정산에 새 값이 모두 반영되어야 합니다.

#### P2-6. 상단 요약 타일과 "할 수 있는 것" 카드의 hover 효과 (#22, #28) [확인]
- **현상:** 상단 요약 타일(`.bento .tile`: 오늘 출발/여행 기간/들를 곳/이동)과 홈의 "XenoTravel로 할 수 있는 것" 카드(`.feats li`)에 hover와 포커스 스타일이 없습니다.
- **완료 기준**
  - 타일은 누를 수 있는 버튼으로 바꾸고, 각각 다음 동작을 연결합니다.
    - 오늘 출발 / D-day → 오늘(또는 Day 1)로 이동
    - 여행 기간 → 날짜 선택기 열기
    - 들를 곳 → 장소 모아보기(P2-3)
    - 이동(직선) → 지도 전체 동선
  - hover와 focus-visible이 같은 표현을 씁니다. 예: 테두리를 강조색으로, 2px 위로 띄우기, 그림자, 커서 포인터.
  - 모바일은 눌렀을 때의 active 상태로 같은 피드백을 줍니다. `prefers-reduced-motion`이면 이동 효과를 끕니다.
  - "할 수 있는 것" 카드도 같은 hover 토큰을 쓰고, 누르면 해당 기능으로 이동하거나 짧은 안내를 보여 줍니다(결정 필요).

#### P2-7. 내 여행 대표 이미지 (#16) [확인]
- **현상:** 여행 카드 커버(`.tc-cover`)는 여행지 이름 해시로 고른 단색 그라데이션과 D-day 글자뿐입니다.
- **완료 기준**
  - 기본 커버: 국가·도시별로 준비한 일러스트 또는 라이선스가 확인된 사진을 씁니다. 해당하는 이미지가 없으면 그라데이션과 패턴을 씁니다(디자인 결정 필요).

    - 업로드한 뒤 16:9로 자르고, 300KB 이하로 압축합니다.

  - 백업 JSON에 포함할지, 공유 링크에 노출할지는 결정이 필요합니다. 기본값은 공유 링크 제외로 둡니다.

#### P2-8. "요즘 뜨는 곳"과 "많이 가는 곳" 함께 제공 (#12) [확인]
- **현상**

#### P2-9. 지도 색상 (#7) [확인]

- **완료 기준**

  - 일차별 경로 색과 마커 번호가 새 바탕 위에서도 WCAG 3:1 이상 대비를 유지해야 합니다.
  - 인쇄용 미니맵(`printMaps`)도 같은 타일로 바꿉니다.

## PART F. 점검 중 직접 찾은 개선 제안 (요청 목록에 없던 것)

> 형식: **제안 영역 / 근거(이번에 확인한 사실) / 구현 방향 / 기대 효과**. 위에서부터 우선순위 순입니다.

### F-1. 여행 데이터 유실 방지 ★ 가장 먼저 권장
- **근거**
  - 모든 데이터가 이 브라우저의 localStorage 한 곳에만 있습니다.
  - 브라우저에 "지우지 말아 달라"고 요청하는 `navigator.storage.persist()` 호출이 없습니다.
  - 백업은 사용자가 직접 파일을 저장할 때만 생깁니다.
  - iOS·macOS Safari는 사이트를 7일 동안 방문하지 않으면 스크립트로 저장한 데이터를 지울 수 있습니다. 여행 한 달 전에 짜 두고 잊으면 일정이 통째로 사라질 수 있습니다.
- **구현 방향**
  - 첫 저장 때 영구 저장을 요청하고, 거절되면 안내합니다.
  - 헤더 ⋯ 메뉴에 "마지막 백업: n일 전" 배지를 둡니다.
  - 출발 7일 전, 여행 종료 다음 날, 큰 변경 20회 뒤에 백업을 권하는 알림을 띄웁니다.
  - 홈 화면에 설치하도록 안내합니다(설치된 앱은 7일 삭제 대상에서 빠짐).
- **기대 효과:** 서비스 신뢰도에 가장 큰 위험(일정 증발)을 줄입니다.

### F-2. 하루 일정이 현실적인지 자동 점검
- **근거**
  - 일정 카드에 "이동 3.1km(직선)"만 있고 예상 이동 시간이 없습니다.
  - 같은 시각에 두 곳을 넣어도 경고가 없습니다(관련 코드 없음).
  - Day 1 항공편이 21:55 도착인데 오후 장소를 넣어도 아무 안내가 없습니다.
- **구현 방향**
  - 직선 거리에 이동 수단별 계수를 곱해 "예상 이동 약 1시간 10분"을 표시합니다. 계수는 도보·대중교통·택시별로 따로 정합니다.
  - 일차 카드에 경고 칩을 붙입니다.
    - 시간 겹침
    - 항공 도착 전이나 출발 후에 잡힌 장소
    - 하루 이동이 3시간을 넘음
    - 장소가 8곳 이상
  - 경고를 누르면 해당 장소로 이동합니다.
- **기대 효과:** 무리한 일정을 출발 전에 잡아냅니다.

### F-3. 숙소 기준 동선
- **근거:** 숙소는 "오늘 밤 숙소"로만 표시되고, 하루 동선 거리 계산에서 숙소→첫 장소, 마지막 장소→숙소 구간이 빠져 있습니다.
- **구현 방향**
  - 일차 동선을 "숙소 → 장소들 → 숙소" 기준으로 계산하고 "숙소에서 첫 장소까지 n km"를 표시합니다.
  - 숙소를 정하지 않은 기간에는 그 기간 장소들의 중심 지점을 지도에 "숙소 추천 위치"로 보여 줍니다.
- **기대 효과:** 실제 이동 부담을 반영하고, 숙소 선택에 도움이 됩니다.

### F-4. app.js 분리 (유지보수성)
- **근거:** `app.js` 한 파일이 약 6,000줄, 278KB입니다. 지도, 일정, 가계부, 체크리스트, 모달, 홈 화면이 모두 들어 있습니다. 이번 요청(숙소 모달, 공용 Select, 장소 모아보기 등)을 그대로 얹으면 한 파일이 더 커지고, 수정할 때마다 다른 기능을 깨뜨릴 위험이 커집니다.
- **구현 방향**
  - Phase 3 기능을 추가하기 전에 화면 단위로 나눕니다: `pages/plan.js`, `pages/budget.js`, `pages/check.js`, `map/*.js`, `ui/`(Select, Sheet, Modal, TimeField, FAB).
  - 동작은 바꾸지 않는 순수 리팩터링으로 진행하고, 기존 테스트가 전부 통과해야 합니다.

### F-5. 첫 로딩 속도 (로밍 환경)

## PART G. 보안과 애드센스 준비

> 2026-11-23에 라이브 응답 헤더, 정적 파일 경로, 배포 소스를 직접 확인한 결과입니다.
> XSS 방어(`esc()`로 출력 이스케이프, `safeUrl`로 링크 검사)는 잘 되어 있으므로 바꾸지 않습니다.

### 보안

#### S-1. 보안 응답 헤더 추가 [확인]
- **현상:** 응답 헤더에 `Strict-Transport-Security`만 있습니다. CSP, `X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`가 모두 없습니다. 이 때문에 다른 사이트가 iframe으로 띄워 클릭을 가로채는 클릭재킹에 노출됩니다.
- **완료 기준**
  - `vercel.json`에 다음 헤더를 넣습니다.
    - `X-Content-Type-Options: nosniff`
    - `Referrer-Policy: strict-origin-when-cross-origin`
    - `Permissions-Policy`: 위치 정보만 self, 나머지 기능은 차단
    - `X-Frame-Options: DENY`와 CSP `frame-ancestors 'none'`
  - CSP는 처음에 `Content-Security-Policy-Report-Only`로 배포해 위반 내역을 확인한 뒤 강제 모드로 바꿉니다.
    - 허용 목록: 지도 타일, Photon/Nominatim, open-meteo, 환율 API, 사용 중인 CDN
    - 인라인 스크립트 2개는 nonce 대신 외부 파일로 옮기거나 hash로 허용합니다.
  - 헤더 적용 후 지도, 검색, 날씨, 환율, 공유, 엑셀/PDF/ICS 내보내기가 모두 동작해야 합니다.

#### S-2. 외부 CDN 스크립트 무결성 검사 [확인]
- **현상:** cally, xlsx, Pretendard 글꼴 CSS를 jsDelivr와 cdnjs에서 SRI 없이 불러옵니다.
- **완료 기준**
  - Leaflet과 Sortable처럼 `vendor/` 폴더에 버전을 고정해 직접 호스팅합니다(권장).
  - 직접 호스팅이 어려운 파일에는 `integrity`와 `crossorigin="anonymous"`를 붙입니다.
  - 서비스워커의 라이브러리 캐시 목록(`LIB_URLS`)도 같이 바꾸고, 캐시 버전을 올립니다.

#### S-3. 엑셀 라이브러리 업데이트 [확인]
- **현상:** cdnjs의 SheetJS 0.18.5를 씁니다. 알려진 취약점이 있는 오래된 버전입니다. 지금은 내보내기에만 써서 위험은 낮습니다.
- **완료 기준**
  - SheetJS 공식 배포처의 최신 버전으로 바꾸고 `vendor/`에 둡니다.
  - 페이지를 열 때가 아니라 [엑셀 내보내기]를 누를 때 동적으로 불러옵니다(첫 로딩도 빨라짐).
  - 내보낸 파일 내용이 이전 버전과 같아야 합니다(시트, 열, 서식).

#### S-4. 출력 이스케이프 통일 [확인]
- **위치:** `app.js` 1515행(`leg.url`), 1902행(`url`)
- **현상:** 앱이 좌표로 만든 구글맵 주소라 지금은 안전하지만, 다른 링크와 달리 이스케이프 없이 href에 들어갑니다.
- **완료 기준**
  - 모든 `href` 출력은 `safeUrl` 검사와 `esc()`를 거칩니다.
  - 이를 확인하는 정적 검사 테스트를 추가합니다: href 템플릿에 `esc(` 없이 `${`가 들어가면 실패하는 테스트.

#### S-5. 가져오는 데이터의 크기 제한 [확인]
- **위치:** `lib/model.js`의 `validateTrip`, 공유 링크 해석(`lib/share.js`), 장소 일괄 가져오기
- **현상:** 형식은 검사하지만 장소 수, 글자 수, 전체 크기는 제한하지 않습니다.
- **완료 기준(기본값, 조정 가능)**
  - 여행 1개: 일수 최대 120일, 장소 최대 2,000개, 지출 최대 5,000건
  - 이름은 200자, 메모는 5,000자, URL은 2,000자까지
  - 공유 링크 코드는 최대 200KB
  - 제한을 넘으면 기존 데이터를 건드리지 않고 이유를 안내합니다(4개 국어).
  - 단위 테스트로 경계값(제한 이하, 정확히 제한, 제한 초과)을 확인합니다.

#### S-6. 짧은 공유 링크 서버 보호 [부분 확인: `/api/share/<id>` 존재]
- **완료 기준**
  - 저장 요청에 IP 기준 횟수 제한을 둡니다(예: 분당 10회).
  - 본문 크기 제한은 S-5와 같은 값으로 맞춥니다.
  - 공유 데이터에 만료 기간(예: 180일)을 두고 그 뒤 삭제합니다.
  - 공유 페이지(`/s/<id>`)와 API 응답에 `X-Robots-Tag: noindex`를 붙입니다.
  - 서버에서도 `CODE_RE` 형식을 검사해 다른 형식은 거부합니다.
  - 개인정보처리방침에 보관 기간을 적습니다.

#### S-7. 공유할 때 개인정보 기본 제외 [미확인: 기본값 확인 필요]
- **완료 기준**
  - 공유 창의 "메모·예약번호 빼고 공유" 옵션이 기본으로 켜져 있어야 합니다.
  - 항공편 예약번호와 숙소 예약번호, 전화번호(P2-1)는 옵션을 꺼야만 포함됩니다.

#### S-8. 이 기기에서 내 데이터 모두 지우기
- **완료 기준**
  - ⋯ 메뉴에 [이 기기에서 모든 데이터 지우기]를 둡니다.
  - 누르면 확인 창에 지워질 여행 수를 보여 주고, [백업 후 지우기]를 함께 제공합니다.
  - localStorage, IndexedDB(P2-7 커버 이미지), 서비스워커 캐시를 모두 지웁니다.

### 애드센스 준비

#### A-1. 자체 도메인 연결 [확인]
- **현상:** `xenotravel.vercel.app`은 Vercel의 도메인이라 루트에 ads.txt를 둘 수 없어 애드센스에 사이트를 등록할 수 없습니다.
- **완료 기준**
  - 자체 도메인을 Vercel에 연결하고, `vercel.app` 주소는 자체 도메인으로 301 리다이렉트합니다.
  - 공유 링크 서버와 OG 이미지의 절대 주소를 새 도메인으로 바꿉니다.
  - 예전 공유 링크(`vercel.app/s/...`)는 계속 열려야 합니다.
- **도메인 확정: `xenoday.com`** (사용자가 구매 후 진행)
  - 정식 주소: `https://xenoday.com`
  - `www.xenoday.com`은 정식 주소로 301 리다이렉트합니다.
  - `xenotravel.vercel.app`의 모든 경로(해시 포함)는 같은 경로의 `xenoday.com`으로 301 리다이렉트합니다.
  - 예전 짧은 공유 링크 `xenotravel.vercel.app/s/<id>`는 리다이렉트 후에도 같은 일정이 열려야 합니다.

#### A-1b. 앱 이름을 XenoDay로 변경 (확정, 2026-11-23)
- 표기 원칙
  - 4개 국어 모두 로마자 "XenoDay"로 씁니다. 번역하거나 음역하지 않습니다.
  - 한국어 문장 안에서 발음 표기가 필요하면 "제노데이"를 씁니다.
  - 화면 제목의 부제: KO "가볍게 짜는 해외여행 일정", EN·ZH·JA는 기존 번역을 따릅니다.
- 이미지 자산: 로고, 파비콘, 앱 아이콘(manifest icons), `og.png`에 "XenoTravel" 글자가 있으면 새 이미지로 바꿉니다. 이미지 원본이 없으면 바꿔야 할 파일 목록만 보고합니다.
- 다음 위치의 문구를 4개 국어 모두 바꿉니다.
  - 화면: 화면 제목(`<title>`), 헤더 로고 글자, 푸터 저작권, "XenoTravel로 할 수 있는 것"
  - 메타 정보: OG/트위터 메타, `manifest.webmanifest`의 name/short_name
  - 공유 메시지: 공유 문구, 카톡 미리보기

- 백업 JSON 파일명과 형식은 예전 파일도 계속 불러올 수 있어야 합니다.
- 공유 링크 코드 형식(`CODE_RE`)은 그대로 둡니다.
- 테스트: 예전 이름으로 저장된 데이터와 백업 파일, 예전 공유 링크가 새 이름의 앱에서 그대로 열려야 합니다.

- 검색 이전: 배포 후 Google Search Console에 새 도메인을 등록하고 "주소 변경"을 신청합니다. 이 작업은 사용자가 직접 하므로 체크리스트만 보고합니다.

#### A-2. robots.txt, sitemap.xml, ads.txt [확인: 모두 404]
- **완료 기준**
  - `robots.txt`: 전체 허용, `/api/`와 `/s/`는 제외, sitemap 위치를 명시합니다.
  - `sitemap.xml`: A-3, A-4, A-5의 정적 페이지를 언어별로 모두 넣습니다(hreflang 포함). 모든 주소는 영문 경로여야 합니다(예: `/ko/guides/shanghai/`, `/en/privacy/`).
  - `ads.txt`: 애드센스 게시자 ID가 정해지면 넣을 수 있게 빈 템플릿과 주석을 둡니다.
  - 세 파일이 정확한 `Content-Type`(text/plain, application/xml)으로 200 응답해야 합니다.

#### A-3. 개인정보처리방침 고정 페이지 [확인: 팝업만 있음, `/privacy` 404]
- **완료 기준**
  - `/privacy`를 JS 없이도 읽히는 정적 HTML로 만들고(4개 국어), 기존 팝업은 이 내용을 그대로 씁니다(한 곳에서 관리).
  - 다음 내용을 추가합니다.
    - 구글 애드센스와 제3자 광고 쿠키 사용
    - 광고 개인화를 끄는 방법(구글 광고 설정 링크)
    - 공유 링크 서버 보관 기간(S-6)
    - 외부 API로 보내는 정보(검색어, 좌표)
  - 푸터와 모든 정적 페이지에서 링크합니다.

#### A-4. 소개, 문의, 이용약관 페이지 [확인: `/about` 404]
- **완료 기준**
  - `/about`(운영 목적, 운영자), `/contact`(이메일 또는 문의 폼), `/terms`(이용약관)을 정적 페이지로 만듭니다.
  - 모든 페이지에 공통 헤더와 푸터 내비게이션을 넣습니다.
  - 문의 폼을 만든다면 스팸 방지(허니팟 등)를 넣고, 개인정보 수집 항목을 방침에 적습니다.

#### A-5. 검색에 노출되는 콘텐츠 페이지 [확인: 사실상 1페이지]
- **현상:** 주소가 `#/` 해시 방식이라 검색엔진에는 홈 한 페이지만 보이고, 내용도 JS로 그려집니다. 도구형 사이트는 "가치가 낮은 콘텐츠"로 거절되기 쉽습니다.
- **완료 기준**
  - 정적 콘텐츠 영역(예: `/guides/`)을 만들고, 빌드 때 마크다운을 HTML로 바꿉니다.
  - 첫 배포 목표는 10~20개 페이지입니다.
    - 사용법: 일정 짜기, 가계부, 공유, 백업
    - 도시 가이드: trends 데이터가 있는 도쿄·오사카·교토·후쿠오카부터
  - 각 페이지에 고유한 title, description, canonical, OG 태그, hreflang을 넣습니다.
  - 가이드에서 "이 도시로 일정 만들기" CTA를 누르면 앱으로 이어집니다.
  - **이미 작성된 초안 5편(상하이·도쿄·오사카·교토·후쿠오카)은 PART H를 따릅니다.** 아래 기준은 이후 추가로 쓰는 도시에 적용합니다.
  - 본문 초안은 Claude Code가 씁니다. 사용자가 검수한 뒤 공개합니다.
    - 도시별로 최소 1,200자 이상의 고유한 글을 씁니다. 다른 도시 글을 복사해 이름만 바꾸지 않습니다.
    - 구성: 언제 가면 좋은지, 동선 예시(2박 3일·4박 5일), 교통·결제 팁, XenoTravel로 일정 짜는 법
    - 운영시간, 가격, 비자, 교통 요금처럼 바뀌는 사실은 출처 링크와 "확인일"을 함께 적습니다. 확인할 수 없으면 `TODO(확인 필요)`로 표시하고 지어내지 않습니다.
    - 초안 파일은 `draft: true`로 두어 사이트맵과 검색 노출에서 빼고, 사용자가 `draft: false`로 바꾸면 공개되게 합니다.
    - 4개 국어는 한국어 원문을 먼저 확정한 뒤 번역합니다(번역본도 검수 대상).

#### A-6. 유럽·영국 쿠키 동의(CMP)
- **완료 기준**
  - 광고 스크립트를 넣는 시점에 구글 인증 CMP(애드센스의 "개인정보 보호 및 메시지" 기능)를 연결합니다.
  - 동의 전에는 개인화 광고 쿠키를 쓰지 않습니다.
  - CSP(S-1) 허용 목록에 광고와 CMP 도메인을 추가합니다.

#### A-7. 광고 위치 기준
- **완료 기준**
  - 광고는 홈 하단, 가이드 본문 중간·하단, 가계부 페이지 맨 아래에만 둡니다.
  - 지도, 드래그 목록, 하단 탭, 플로팅 버튼(FAB), 모달 안, 공유 보기 화면에는 넣지 않습니다. 실수 클릭을 유도하면 정책 위반입니다.
  - 광고 영역은 높이를 미리 확보해 레이아웃 이동(CLS)이 없게 합니다.
  - 모바일 337px에서 가로 넘침이 없어야 합니다.
  - 광고 코드는 A-1~A-6 완료와 애드센스 승인 뒤에만 켭니다. 그 전에는 설정 플래그로 꺼 둡니다.

## PART H. 여행 가이드 초안 반영 (A-5 구체화)

> 함께 전달한 `content/guides/` 폴더에 한국어 초안 5편과 사진이 들어 있습니다. 모두 `draft: true` 상태입니다.
> A-5의 정적 가이드 페이지는 이 파일들을 그대로 원본으로 씁니다.

### 전달 파일

| 파일 | 도시 | 종류 | 사진 | 남은 TODO |
| --- | --- | --- | --- | --- |
| `content/guides/shanghai.ko.md` | 상하이 | 직접 방문 후기(`experience: true`, 2026-11-07 방문) | 20장 (`images/shanghai/`) | 사진 4장, 관광버스 요금, 딘딘 영상 링크, 알리페이 수수료 |

### H-1. 가이드 페이지 생성
- **완료 기준**
  - 빌드 때 `content/guides/*.ko.md`를 읽어 정적 HTML을 만듭니다. JS 없이도 본문이 보여야 합니다.
  - **주소 규칙(영문만 사용):**
    - `slug`는 소문자 영문, 숫자, 하이픈만 허용합니다(`^[a-z0-9-]+$`). 한글이 섞여 있거나 형식이 다르면 빌드를 실패시킵니다.
    - 언어 접두어를 씁니다.
      - 한국어: `/ko/guides/shanghai/`
      - 영어: `/en/guides/shanghai/`
      - 중국어: `/zh/guides/shanghai/`
      - 일본어: `/ja/guides/shanghai/`
    - `slug`는 4개 언어가 같은 값을 씁니다. 번역본끼리는 `hreflang`으로 연결하고, `x-default`는 영어로 둡니다.
    - `/guides/shanghai/`(접두어 없음)는 브라우저 언어(P0-7 규칙)에 맞는 언어 주소로 302 리다이렉트합니다. 해당 언어 번역이 없으면 한국어로 보냅니다.
    - 목록 페이지: `/ko/guides/`, `/en/guides/` …
    - 이미지 파일명도 영문 소문자와 하이픈만 씁니다(현재 파일들은 이미 이 형식).
  - frontmatter 필드: `title`, `slug`, `city`, `country`, `lang`, `draft`, `updated`, `description`, `sources[]`, 그리고 선택 필드 `experience`, `visited`
  - `title`은 `<title>`과 OG 제목으로, `description`은 meta description과 OG 설명으로 씁니다.
  - `sources[]`는 본문 끝에 "출처(확인일)" 목록으로 출력합니다.
  - `experience: true`인 글은 제목 아래에 "직접 다녀온 후기 · 2026년 11월 방문" 배지를 붙입니다. 날짜는 `visited` 값을 씁니다.
  - `/guides/` 목록 페이지: 도시 카드(제목, 설명, 최종 수정일)를 보여 주고, 방문 후기를 먼저 정렬합니다.

### H-2. 초안(draft) 처리
- **완료 기준**
  - `draft: true`인 글은 운영 빌드에서 페이지를 만들지 않습니다. 사이트맵, 목록, 검색에서도 모두 뺍니다.
  - 미리보기 배포(Vercel Preview)에서만 `noindex`를 붙여 페이지를 만들고, 상단에 "초안" 띠를 표시합니다.
  - 사용자가 `draft: false`로 바꾸면 다음 운영 배포에 공개되고 사이트맵에 추가됩니다.

### H-3. TODO와 주석 처리
- **완료 기준**
  - 본문의 HTML 주석(`<!-- TODO(...) -->`)은 화면에 출력하지 않습니다.
  - 본문 텍스트에 남은 `TODO(확인 필요)`가 하나라도 있으면 그 글은 `draft: false`여도 운영 빌드를 실패시키고, 파일명과 줄 번호를 출력합니다. 확인되지 않은 정보가 공개되는 것을 막기 위해서입니다.
  - 빌드 로그 끝에 글별 남은 TODO 개수 요약을 출력합니다.

### H-4. 이미지
- **완료 기준**
  - `content/guides/images/<slug>/`의 이미지를 빌드 때 WebP로 변환합니다(가로 1600px·800px 두 크기, `srcset`).
  - 원본 JPG는 대체 이미지로 유지합니다.
  - 본문 이미지는 `loading="lazy"`를 쓰고 `width`·`height`를 지정해 레이아웃 이동(CLS)이 없게 합니다.
  - 마크다운 이미지 바로 다음 줄의 이탤릭 문장(`*...*`)은 `<figcaption>`으로 묶습니다.
  - alt 텍스트는 마크다운에 적힌 그대로 씁니다. 빈 alt는 빌드 경고를 냅니다.
  - **얼굴 블러는 사용자가 직접 처리합니다.** 다음 3장은 공개 전에 사용자가 교체할 예정이니 파일명을 유지합니다: `peoples-square-restroom-line.jpg`, `peoples-square-starbucks.jpg`, `mms-store.jpg`
  - `dindin-youtube-capture.jpg`는 캡션에 출처 링크가 없으면 빌드 경고를 냅니다.

### H-5. 앱 연결
- **완료 기준**
  - 글 끝의 "XenoDay로 이 코스 짜기" 아래에 [이 도시로 일정 만들기] 버튼을 둡니다. 누르면 홈의 새 여행 만들기에 도시를 채운 상태로 이동합니다. 주소에는 영문 도시 id를 씁니다(예: `/#/?dest=shanghai`). 화면에는 현재 언어의 도시 이름(상하이 / Shanghai / 上海 / 上海)으로 표시합니다.
  - 상하이 글에는 [이 코스 그대로 불러오기] 버튼도 둡니다. 누르면 글에 나온 장소 9곳(신천지, 예상하이, 티엔즈팡, 예원, 인민광장, 난징동루, 와이탄, 관광버스 정류장, The Fellas Terrace)을 장소 보관함에 담은 새 여행을 만듭니다.
    - 장소 좌표는 빌드 때 고정 데이터로 넣고, 런타임에 지오코딩하지 않습니다(P0-1 교훈).
    - TODO(확인 필요): 관광버스 정류장 위치는 사용자에게 확인한 뒤 넣고, 확인 전에는 9곳 중 이 항목을 뺍니다.
  - 홈 화면의 "요즘 뜨는 곳" 아래에 "여행 가이드" 섹션(최신 3편)을 추가합니다.

### H-6. 번역
- 한국어 원문이 `draft: false`로 확정된 글만 EN·ZH·JA로 번역합니다(`<slug>.en.md` 등).
- 번역본도 `draft: true`로 만들고 사용자 검수 후 공개합니다.
- 고유명사(상호, 지명)는 현지 표기를 함께 적습니다. 예: 예상하이(夜上海, Ye Shanghai)
