## PART B. 이슈 상세 (Codex·Claude Code 공용 작업 기준)

> 형식: **위치 / 현재 현상 / 원인 / 완료 기준**. 요청자 번호는 (#n)으로 함께 적었습니다.

### Phase 1 — P0 · 데이터와 동작 오류

#### P0-1. 여행지 좌표가 엉뚱한 나라로 잡힘 (신규 발견) [확인]
- **위치:** 홈의 새 여행 만들기 → `geocodeDestination` (`lib/geo.js` 61행), 호출부 `app.js` 3110행 부근
- **현상:** 자동완성에서 "자싱 · 중국"을 골라 만들었는데 저장된 값이 `center: 24.14, 74.95`, `country: "in"`(인도 라자스탄)이었습니다. 그 결과 다음 문제가 함께 생겼습니다.
  - 장소가 없는 날의 지도가 인도로 이동하고, 길게 누르면 "Bardal, Madhya Pradesh, India"가 나옵니다.
  - 장소 검색 결과에 "여행지에서 4548km"처럼 거리가 잘못 표시됩니다.
  - 장소가 없는 날의 날씨가 인도 기준(최고 33°C)으로 나옵니다.
- **원인:** 자동완성 목록(`DESTINATIONS`)에는 좌표가 없습니다. 그래서 한국어 "자싱"을 Nominatim에 그대로 보내고, 첫 결과를 신뢰합니다. 고른 국가와 결과 국가가 같은지도 검증하지 않습니다.
- **완료 기준**
  - 자동완성 목록의 도시는 고정 좌표와 국가 코드를 가지며, 이 값을 쓰면 지오코딩을 하지 않습니다.
  - 목록에 없는 도시는 영어 별칭과 국가 필터로 조회합니다. 결과 국가가 고른 국가와 다르면 버립니다.
  - 여행 정보 화면에 "여행지 위치"를 작은 지도로 보여 주고 다시 고를 수 있게 합니다.
  - 이미 저장된 여행은 마이그레이션 시 `center`가 담긴 장소 평균과 300km 넘게 떨어져 있으면 장소 평균으로 고칩니다.
  - 사용자의 실제 "자싱 여행" 날씨(Day 2 "소나기 24°/18°")가 자싱 좌표로 계산된 값인지 함께 확인합니다.

#### P0-2. 항공편이 Day 1 / 마지막 날에 붙지 않음 (#3) [확인]
- **위치:** `lib/model.js`의 `flightsOnDate`(706행)와 `dayStays`(575행), 홈 상단 "확인할 것" 경고
- **현상:** 출국편(OZ367, 11/22 20:45 출발)이 여행 시작일(11/23)보다 하루 앞서면 일정에 아예 안 나옵니다. 대신 "여행 기간 밖 항공편 1개는 일정에 안 보여요" 경고만 뜹니다.
- **원인:** 항공편을 종류(출국·귀국)가 아니라 날짜가 같은지로만 일차에 붙입니다.
- **완료 기준**
  - **출국편**은 날짜와 상관없이 Day 1 맨 위 카드로 보입니다. 날짜가 시작일보다 앞이면 "전날 출발" 배지를 붙입니다.
  - **귀국편**은 마지막 날 맨 아래에 보입니다. 마지막 날 다음 날 새벽 출발도 같은 위치에 붙입니다.
  - **이동편**(`move`)은 지금처럼 날짜로 붙입니다.
  - 기간 밖 날짜로 저장할 때 선택지를 줍니다: [여행 기간을 11/22까지 늘리기] [기간은 그대로, Day 1에 붙이기].
  - 출국·귀국편이 여러 개면 시간순으로 모두 보여 줍니다.
  - 항공편 시간대 표기는 "현지 시각" 원칙을 유지합니다.
  - 인쇄/PDF와 ICS 내보내기에도 같은 위치로 나와야 합니다.

#### P0-3. 체크 해제해도 가계부 지출이 남음 (#24) [확인]
- **위치:** `lib/checklist.js`의 `toggleCheck`, `app.js`의 `#page-check` change 핸들러
- **현상:** 가격이 있는 항목을 체크하면 지출이 자동 기록됩니다. 그런데 체크를 풀어도 지출이 그대로 남고, "가계부 지출은 그대로 남겼어요"라는 토스트만 뜹니다.
- **완료 기준 (정책)**
  - 체크로 **자동 생성된 지출**(`checkId` 연결)이고 금액을 사용자가 고치지 않았다면, 체크 해제 시 지출도 삭제합니다. 토스트에 [실행 취소]를 넣습니다.
  - 사용자가 "결제" 금액을 고친 지출이면 확인 창을 띄웁니다: [지출도 삭제] [체크만 해제] [취소].
  - 가계부 화면에 체크리스트에서 온 지출임을 아이콘으로 표시합니다.

#### P0-4. "전체 해제" 확인 창에 선택지가 하나뿐 (#26) [확인]
- **위치:** `app.js`의 `changeCheckGroup` → `ask({ title: '전체 해제', actions: [체크만 해제] })`
- **현상:** "연결된 지출 4건: ¥90, ¥220, ¥110, ¥123" 안내 아래에 버튼이 "체크만 해제" 하나뿐입니다. 지출도 함께 정리하는 길이 없습니다.
- **완료 기준**
  - 버튼은 [체크 해제 + 지출 4건 삭제] [체크만 해제] [취소] 세 개입니다. 기본 포커스는 P0-3 정책과 같은 쪽에 둡니다.
  - 금액을 고친 지출이 섞여 있으면 본문에 "직접 고친 지출 n건은 남깁니다"를 명시합니다.
  - 결과 토스트에 [실행 취소]를 넣습니다.
  - 4개 국어 문구를 모두 추가합니다.

#### P0-5. 가계부 "날짜별" 막대가 카드 밖으로 넘쳐 페이지 전체가 가로로 밀림 (#13, #9) [확인]
- **위치:** `#page-budget .daybars` (`.grid2 > .box`)
- **현상:** 20일 여행에서 페이지 폭이 337px일 때 524px, 480px일 때 527px로 늘어납니다. 모바일 하단 탭 버튼(`.pg.trip-only`)이 화면 밖으로 밀리고, D13 이후는 카드 밖으로 넘칩니다. 4개 국어 모두 같습니다.
- **완료 기준**
  - 막대 차트는 카드 폭을 절대 넘지 않습니다.
  - 일수가 많으면 막대 폭을 줄이고, 라벨은 n일 간격으로만 표시합니다. 또는 카드 안에서만 가로 스크롤되게 하고 양끝을 페이드 처리합니다(결정 필요).
  - 30일 이상이면 주 단위로 묶어 보여 줍니다.
  - 모든 페이지가 320~767px에서 scrollWidth와 clientWidth가 같아야 합니다.

#### P0-6. 새 여행 모달이 좌측 하단에 붙고 아래가 잘림 (#8) [확인]
- **위치:** `#new-trip-modal` (dialog)
- **현상:** 865px 폭에서 모달이 `position: fixed; margin: 774px 0 0; left: 0; width: 520px`로 잡힙니다. 그래서 화면 왼쪽 아래에 반쯤 걸치고, 아래쪽(높이 244px 중 일부)은 화면 밖으로 잘립니다. 모바일용 바텀시트 규칙에 데스크톱 폭(520px)이 섞여 있는 상태입니다.
- **완료 기준**
  - 600px 이상: 화면 중앙 모달(최대 폭 560px), 입력칸과 날짜 버튼이 한 줄에 잘리지 않습니다.

  - 항공편·공유·보관함 가져오기 등 모든 dialog가 같은 Modal/Sheet 컴포넌트를 씁니다.

#### P0-7. 브라우저 언어를 따르지 않고 항상 한국어로 시작 (#11) [확인]

- **완료 기준**
  - 저장된 언어가 없을 때만 `navigator.languages`를 앞에서부터 확인합니다.
    - `ko*` → 한국어
    - `ja*` → 일본어
    - `zh`, `zh-CN`, `zh-SG`, `zh-Hans*` → 중국어 간체
    - `zh-TW`, `zh-HK`, `zh-Hant*` → 중국어 간체로 표시(번체 지원 전까지)
    - `en*` → 영어

- **현상(재현)**
  - 여행 시작일이 11/23인 여행에서 숙소 달력을 열면 11/22 이전이 회색(선택 불가)이고, 이전 달 화살표도 막혀 있습니다.

  - 숙소의 `startIndex`
  - 지출의 `day`
  - 확인 창에 "날짜만 바뀌어요"라는 문구가 있지만, 날짜를 그대로 두는 선택지는 없습니다.
- **완료 기준**
  - 숙소 달력에서 여행 기간 밖 날짜도 고를 수 있게 합니다. 바깥 날짜는 흐리게 표시하되 비활성으로 막지 않습니다.

  - 여행 날짜 변경에 **"날짜 기준 유지"를 기본값**으로 추가합니다. 시작일을 k일 앞당기면 다음처럼 처리하고, 장소는 원래 날짜에 그대로 둡니다.
    - 앞에 빈 날 k개를 추가합니다.
    - 숙소 `startIndex`와 지출 `day`를 +k 합니다.
    - 시작일을 늦추면 반대로 처리하고, 잘려 나가는 날의 장소는 보관함으로 보냅니다.
  - 기존 "일차 기준 유지(모두 같이 밀기)"는 두 번째 선택지로 남깁니다.
  - 항공편 저장(P0-2)과 새 숙소 모달(P2-1)도 같은 "기간 늘리기" 흐름을 씁니다.
  - 테스트 1: 11/23 시작 여행에 Day 1 장소, 숙소, 지출이 있는 상태에서 시작일을 11/22로 바꿉니다. 그 뒤에도 장소, 숙소, 지출이 11/23 날짜에 그대로 있어야 합니다.
  - 테스트 2: 오늘 이전 날짜(지난 여행)에서도 위 두 흐름이 똑같이 동작해야 합니다.

  - 기존 `trip.stays` 데이터와 호환되어야 하고, 일정 화면의 "숙소로 추가"는 이 모달을 여는 바로가기로 바꿉니다.

#### P2-2. 다른 일차로 "복제"는 여러 날 선택 (#20) [확인]
- **위치:** 이동/복제 다이얼로그(`app.js` 5421행 부근). 현재 두 모드 모두 라디오 버튼입니다.
- **완료 기준**
  - 이동은 라디오(하나만 선택)를 유지합니다.
  - 복제는 체크박스(여러 날 선택)로 바꾸고, 상단에 [전체 선택] [전체 해제]를 두며 선택 개수를 표시합니다. 지금 날짜는 비활성화합니다.
  - 이미 같은 장소가 있는 날은 "이미 있음" 표시를 하고 기본으로 선택하지 않습니다.
  - [n개 날에 복제] 버튼과 [실행 취소] 토스트를 둡니다.

#### P2-3. 장소 모아보기 — 중복을 합치고 일괄 삭제 (#21)
- **현상:** 같은 장소(南湖: Day 1·2, 月河历史街区: Day 1·4)가 여러 날에 있어도 한눈에 볼 방법이 없습니다.
- **완료 기준**
  - 일정 화면에 [장소 모아보기] 뷰를 추가합니다(상단 요약의 "들를 곳 n곳"을 눌러도 열림, P2-6 참고).
  - 같은 장소 판정 기준: 이름이 같고 좌표가 50m 안이거나, 같은 구글맵 URL이면 같은 장소로 묶습니다.
  - 각 행에 장소명, "Day 1 · Day 2 · 보관함" 칩(누르면 그 일차로 이동), 등장 횟수, [지도에서 보기], [모든 일정에서 삭제]를 둡니다.
  - [모든 일정에서 삭제]는 "3개 일정에서 삭제할까요?"로 확인한 뒤 삭제하고 [실행 취소]를 제공합니다. 연결된 지출이 있으면 지출은 남긴다고 안내합니다.
  - 정렬: 방문 순 / 이름순 / 등장 횟수순

#### P2-4. 스마트 준비물 추천에 전체 선택 (#25) [확인]
- **현상:** 추천 12개에 각각 체크박스만 있고, 전체 선택이나 해제가 없습니다.
- **완료 기준**
  - 맨 위에 전체 선택 체크박스를 두고, 일부만 선택된 상태(indeterminate)도 표시합니다.
  - 그룹(출발 전 / 짐 싸기 / 쇼핑)마다 그룹 단위 전체 체크를 둡니다.
  - "선택한 n개 추가" 숫자가 실시간으로 바뀌고, 0개면 버튼을 비활성화합니다.

#### P2-5. 결제 수단에 신용카드 추가 (#27) [확인]
- **현재:** `PAYMENTS = 현금 / 카드 / 교통카드 / 트래블카드`
- **완료 기준**
  - "카드"를 **신용카드**와 **체크카드**로 나눕니다. 기존 `card` 값은 신용카드로 보고 마이그레이션합니다.
  - **간편결제**(Alipay, WeChat Pay, Apple Pay 등)를 추가합니다. 중국 여행은 실제로 간편결제 비중이 커서 이 항목이 없으면 기록이 어긋납니다.
  - 결제 수단 차트, CSV/엑셀 내보내기, 정산에 새 값이 모두 반영되어야 합니다.

#### P2-6. 상단 요약 타일과 "할 수 있는 것" 카드의 hover 효과 (#22, #28) [확인]
- **현상:** 상단 요약 타일(`.bento .tile`: 오늘 출발/여행 기간/들를 곳/이동)과 홈의 "XenoTravel로 할 수 있는 것" 카드(`.feats li`)에 hover와 포커스 스타일이 없습니다.
- **완료 기준**
  - 타일은 누를 수 있는 버튼으로 바꾸고, 각각 다음 동작을 연결합니다.
    - 오늘 출발 / D-day → 오늘(또는 Day 1)로 이동
    - 여행 기간 → 날짜 선택기 열기
    - 들를 곳 → 장소 모아보기(P2-3)
    - 이동(직선) → 지도 전체 동선
  - hover와 focus-visible이 같은 표현을 씁니다. 예: 테두리를 강조색으로, 2px 위로 띄우기, 그림자, 커서 포인터.
  - 모바일은 눌렀을 때의 active 상태로 같은 피드백을 줍니다. `prefers-reduced-motion`이면 이동 효과를 끕니다.
  - "할 수 있는 것" 카드도 같은 hover 토큰을 쓰고, 누르면 해당 기능으로 이동하거나 짧은 안내를 보여 줍니다(결정 필요).

#### P2-7. 내 여행 대표 이미지 (#16) [확인]
- **현상:** 여행 카드 커버(`.tc-cover`)는 여행지 이름 해시로 고른 단색 그라데이션과 D-day 글자뿐입니다.
- **완료 기준**
  - 기본 커버: 국가·도시별로 준비한 일러스트 또는 라이선스가 확인된 사진을 씁니다. 해당하는 이미지가 없으면 그라데이션과 패턴을 씁니다(디자인 결정 필요).
  - 사용자가 사진을 바꿀 수 있게 합니다.
    - 업로드한 뒤 16:9로 자르고, 300KB 이하로 압축합니다.
    - **IndexedDB**에 저장합니다. localStorage 5MB 한도 때문입니다.
    - [기본으로 되돌리기]를 둡니다.
  - 백업 JSON에 포함할지, 공유 링크에 노출할지는 결정이 필요합니다. 기본값은 공유 링크 제외로 둡니다.
  - 지난 여행 카드의 채도 낮추기(`.ended`)는 유지합니다.

#### P2-8. "요즘 뜨는 곳"과 "많이 가는 곳" 함께 제공 (#12) [확인]
- **현상**
  - "많이 가는 곳"은 `POPULAR` 배열에 직접 적어 둔 10개 도시라 선정 기준이 없습니다.
  - "요즘 뜨는 곳"은 4개 도시 트렌드 장소입니다.
  - 두 정보가 서로 다른 위치와 단위(도시와 장소)로 나뉘어 있습니다.
- **완료 기준**
  - 도시 데이터 스키마를 `trending[]`(기간 한정, 신규 오픈 등, 조사일 표시)와 `popular[]`(늘 인기 있는 대표 명소)로 나눕니다.
  - 여행 페이지는 탭 두 개 [요즘 뜨는 곳] [많이 가는 곳]으로 같은 카드 형식을 씁니다. 각 탭에 선정 기준을 한 줄로 표시합니다. 예: "2026-11 조사 · 최근 3개월 SNS·뉴스 언급" / "대표 명소 · 편집 선정".
  - 홈 화면의 "많이 가는 곳" 칩은 "추천 여행지"로 이름을 바꾸거나, 실제 생성 수를 기준으로 바꿉니다(결정 필요).
  - 데이터가 없는 도시는 P0-8 규칙을 따릅니다.

#### P2-9. 지도 색상 (#7) [확인]
- **현상:** 바탕 지도가 Esri "World Light Gray / Dark Gray Canvas"라 회색 위주입니다. 경로와 마커 외에는 구분이 약하고 라벨도 흐립니다.
- **완료 기준**
  - 라이트 모드는 색이 있는 일반 지도 스타일로 바꿉니다(물·공원·도로가 구분되는 타일). 다크 모드는 대비가 확보된 다크 타일을 씁니다.
  - 후보 타일 제공자의 이용 약관(상업적 사용, 월 호출 한도, 출처 표기)을 확인하고 결정해야 합니다. 코드 주석에도 "사용자가 늘면 키 기반으로 교체"라고 적혀 있습니다.
  - 지도 오른쪽 위에 [기본 / 회색] 토글을 두는 방안도 검토합니다.
  - 일차별 경로 색과 마커 번호가 새 바탕 위에서도 WCAG 3:1 이상 대비를 유지해야 합니다.
  - 인쇄용 미니맵(`printMaps`)도 같은 타일로 바꿉니다.

#### P2-10. 푸터의 "빌드 e9c75ce" 숨기기 (#18) [확인]
- **이유:** 이전 QA 패치에서 "지금 어떤 배포가 떠 있는지" 확인하려고 커밋 해시를 넣었습니다(`app.js` 3212~3224행, `<meta name="build-commit">`). 일반 사용자에게는 의미 없는 정보입니다.
- **완료 기준**
  - 일반 사용자 화면에서는 숨깁니다. `?debug=1`이거나 ⋯ 메뉴의 "앱 정보"에서만 보여 줍니다.
  - `<meta name="build-commit">`은 QA용으로 유지합니다.
  - 저작권 문구는 "© 2026 XenoTravel"만 남기고, "모든 권리 보유" 유지 여부는 결정이 필요합니다.

## PART F. 점검 중 직접 찾은 개선 제안 (요청 목록에 없던 것)

> 형식: **제안 영역 / 근거(이번에 확인한 사실) / 구현 방향 / 기대 효과**. 위에서부터 우선순위 순입니다.

### F-1. 여행 데이터 유실 방지 ★ 가장 먼저 권장
- **근거**
  - 모든 데이터가 이 브라우저의 localStorage 한 곳에만 있습니다.
  - 브라우저에 "지우지 말아 달라"고 요청하는 `navigator.storage.persist()` 호출이 없습니다.
  - 백업은 사용자가 직접 파일을 저장할 때만 생깁니다.
  - iOS·macOS Safari는 사이트를 7일 동안 방문하지 않으면 스크립트로 저장한 데이터를 지울 수 있습니다. 여행 한 달 전에 짜 두고 잊으면 일정이 통째로 사라질 수 있습니다.
- **구현 방향**
  - 첫 저장 때 영구 저장을 요청하고, 거절되면 안내합니다.
  - 헤더 ⋯ 메뉴에 "마지막 백업: n일 전" 배지를 둡니다.
  - 출발 7일 전, 여행 종료 다음 날, 큰 변경 20회 뒤에 백업을 권하는 알림을 띄웁니다.
  - 홈 화면에 설치하도록 안내합니다(설치된 앱은 7일 삭제 대상에서 빠짐).
- **기대 효과:** 서비스 신뢰도에 가장 큰 위험(일정 증발)을 줄입니다.

### F-2. 하루 일정이 현실적인지 자동 점검
- **근거**
  - 일정 카드에 "이동 3.1km(직선)"만 있고 예상 이동 시간이 없습니다.
  - 같은 시각에 두 곳을 넣어도 경고가 없습니다(관련 코드 없음).
  - Day 1 항공편이 21:55 도착인데 오후 장소를 넣어도 아무 안내가 없습니다.
- **구현 방향**
  - 직선 거리에 이동 수단별 계수를 곱해 "예상 이동 약 1시간 10분"을 표시합니다. 계수는 도보·대중교통·택시별로 따로 정합니다.
  - 일차 카드에 경고 칩을 붙입니다.
    - 시간 겹침
    - 항공 도착 전이나 출발 후에 잡힌 장소
    - 하루 이동이 3시간을 넘음
    - 장소가 8곳 이상
  - 경고를 누르면 해당 장소로 이동합니다.
- **기대 효과:** 무리한 일정을 출발 전에 잡아냅니다.

### F-3. 숙소 기준 동선
- **근거:** 숙소는 "오늘 밤 숙소"로만 표시되고, 하루 동선 거리 계산에서 숙소→첫 장소, 마지막 장소→숙소 구간이 빠져 있습니다.
- **구현 방향**
  - 일차 동선을 "숙소 → 장소들 → 숙소" 기준으로 계산하고 "숙소에서 첫 장소까지 n km"를 표시합니다.
  - 숙소를 정하지 않은 기간에는 그 기간 장소들의 중심 지점을 지도에 "숙소 추천 위치"로 보여 줍니다.
- **기대 효과:** 실제 이동 부담을 반영하고, 숙소 선택에 도움이 됩니다.

## PART G. 보안과 애드센스 준비

> 2026-11-23에 라이브 응답 헤더, 정적 파일 경로, 배포 소스를 직접 확인한 결과입니다.
> XSS 방어(`esc()`로 출력 이스케이프, `safeUrl`로 링크 검사)는 잘 되어 있으므로 바꾸지 않습니다.

### 보안

#### S-1. 보안 응답 헤더 추가 [확인]
- **현상:** 응답 헤더에 `Strict-Transport-Security`만 있습니다. CSP, `X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`가 모두 없습니다. 이 때문에 다른 사이트가 iframe으로 띄워 클릭을 가로채는 클릭재킹에 노출됩니다.
- **완료 기준**
  - `vercel.json`에 다음 헤더를 넣습니다.
    - `X-Content-Type-Options: nosniff`
    - `Referrer-Policy: strict-origin-when-cross-origin`
    - `Permissions-Policy`: 위치 정보만 self, 나머지 기능은 차단
    - `X-Frame-Options: DENY`와 CSP `frame-ancestors 'none'`
  - CSP는 처음에 `Content-Security-Policy-Report-Only`로 배포해 위반 내역을 확인한 뒤 강제 모드로 바꿉니다.
    - 허용 목록: 지도 타일, Photon/Nominatim, open-meteo, 환율 API, 사용 중인 CDN
    - 인라인 스크립트 2개는 nonce 대신 외부 파일로 옮기거나 hash로 허용합니다.
  - 헤더 적용 후 지도, 검색, 날씨, 환율, 공유, 엑셀/PDF/ICS 내보내기가 모두 동작해야 합니다.

#### S-2. 외부 CDN 스크립트 무결성 검사 [확인]
- **현상:** cally, xlsx, Pretendard 글꼴 CSS를 jsDelivr와 cdnjs에서 SRI 없이 불러옵니다.
- **완료 기준**
  - Leaflet과 Sortable처럼 `vendor/` 폴더에 버전을 고정해 직접 호스팅합니다(권장).
  - 직접 호스팅이 어려운 파일에는 `integrity`와 `crossorigin="anonymous"`를 붙입니다.
  - 서비스워커의 라이브러리 캐시 목록(`LIB_URLS`)도 같이 바꾸고, 캐시 버전을 올립니다.

#### S-3. 엑셀 라이브러리 업데이트 [확인]
- **현상:** cdnjs의 SheetJS 0.18.5를 씁니다. 알려진 취약점이 있는 오래된 버전입니다. 지금은 내보내기에만 써서 위험은 낮습니다.
- **완료 기준**
  - SheetJS 공식 배포처의 최신 버전으로 바꾸고 `vendor/`에 둡니다.
  - 페이지를 열 때가 아니라 [엑셀 내보내기]를 누를 때 동적으로 불러옵니다(첫 로딩도 빨라짐).
  - 내보낸 파일 내용이 이전 버전과 같아야 합니다(시트, 열, 서식).

#### S-4. 출력 이스케이프 통일 [확인]
- **위치:** `app.js` 1515행(`leg.url`), 1902행(`url`)
- **현상:** 앱이 좌표로 만든 구글맵 주소라 지금은 안전하지만, 다른 링크와 달리 이스케이프 없이 href에 들어갑니다.
- **완료 기준**
  - 모든 `href` 출력은 `safeUrl` 검사와 `esc()`를 거칩니다.
  - 이를 확인하는 정적 검사 테스트를 추가합니다: href 템플릿에 `esc(` 없이 `${`가 들어가면 실패하는 테스트.

#### S-5. 가져오는 데이터의 크기 제한 [확인]
- **위치:** `lib/model.js`의 `validateTrip`, 공유 링크 해석(`lib/share.js`), 장소 일괄 가져오기
- **현상:** 형식은 검사하지만 장소 수, 글자 수, 전체 크기는 제한하지 않습니다.
- **완료 기준(기본값, 조정 가능)**
  - 여행 1개: 일수 최대 120일, 장소 최대 2,000개, 지출 최대 5,000건
  - 이름은 200자, 메모는 5,000자, URL은 2,000자까지
  - 공유 링크 코드는 최대 200KB
  - 제한을 넘으면 기존 데이터를 건드리지 않고 이유를 안내합니다(4개 국어).
  - 단위 테스트로 경계값(제한 이하, 정확히 제한, 제한 초과)을 확인합니다.

#### S-6. 짧은 공유 링크 서버 보호 [부분 확인: `/api/share/<id>` 존재]
- **완료 기준**
  - 저장 요청에 IP 기준 횟수 제한을 둡니다(예: 분당 10회).
  - 본문 크기 제한은 S-5와 같은 값으로 맞춥니다.
  - 공유 데이터에 만료 기간(예: 180일)을 두고 그 뒤 삭제합니다.
  - 공유 페이지(`/s/<id>`)와 API 응답에 `X-Robots-Tag: noindex`를 붙입니다.
  - 서버에서도 `CODE_RE` 형식을 검사해 다른 형식은 거부합니다.
  - 개인정보처리방침에 보관 기간을 적습니다.

#### S-7. 공유할 때 개인정보 기본 제외 [미확인: 기본값 확인 필요]
- **완료 기준**
  - 공유 창의 "메모·예약번호 빼고 공유" 옵션이 기본으로 켜져 있어야 합니다.
  - 항공편 예약번호와 숙소 예약번호, 전화번호(P2-1)는 옵션을 꺼야만 포함됩니다.

#### S-8. 이 기기에서 내 데이터 모두 지우기
- **완료 기준**
  - ⋯ 메뉴에 [이 기기에서 모든 데이터 지우기]를 둡니다.
  - 누르면 확인 창에 지워질 여행 수를 보여 주고, [백업 후 지우기]를 함께 제공합니다.
  - localStorage, IndexedDB(P2-7 커버 이미지), 서비스워커 캐시를 모두 지웁니다.

### 애드센스 준비

  - `/ko/guides/shanghai/` 등이 200으로 열리고, `sitemap.xml`에도 들어 있으며, `noindex`가 없습니다.
  - 상하이 글 본문에 `TODO(확인 필요)` 문구 3개가 그대로 보입니다(영상 링크, 관광버스 요금, 알리페이 수수료).
  - 얼굴 블러 전 사진 3장(화장실 줄, 스타벅스, M&M's)이 그대로 공개되어 있습니다.
- **원인 추정:** H-2(draft는 운영 빌드 제외)와 H-3(본문에 TODO가 있으면 빌드 실패)가 동작하지 않거나, 원문의 `draft`가 `false`로 바뀌었습니다.
- **완료 기준**
  - 정식 오픈 배포부터: `draft: true`인 글은 운영 사이트, 목록, 사이트맵에서 뺍니다.
  - H-2·H-3 안전장치를 테스트로 고정합니다. 테스트는 두 가지입니다.
    - `draft: true`인 글이 운영 빌드 결과물에 없는지
    - 본문에 `TODO(`가 남은 글을 공개하려 하면 빌드가 실패하는지
  - 사용자가 사진 교체와 TODO 정리를 마치고 `draft: false`로 바꾼 글만 다시 공개합니다.

### I-3. 모바일 지도 하단 시트에서 좌우로 밀어 일차 바꾸기 (#3)
- **현상 [확인]:** 모바일 지도 화면 하단 시트에 "Day 2 · 11/24"가 보이지만, 좌우로 밀어도 일차가 바뀌지 않습니다(관련 코드 없음). 일차를 바꾸려면 위쪽의 작은 ‹ › 화살표만 쓸 수 있습니다.
- **완료 기준**
  - 하단 시트 머리(`#mapSheet .ms-head`)와 시트 본문을 좌우로 밀면 일차가 바뀝니다. 왼쪽으로 밀면 다음 날, 오른쪽으로 밀면 전날입니다.
  - 방향 판정: 처음 10px 움직임에서 가로 이동이 세로보다 크면 "일차 넘기기", 아니면 기존 "시트 높이 조절"로 처리합니다. 한 번의 제스처에서 둘이 동시에 일어나지 않게 합니다.
  - 넘김 기준: 가로 50px 이상, 또는 빠르게 튕긴 경우(속도 0.3px/ms 이상)입니다. 기준에 못 미치면 원위치로 돌아갑니다.
  - 미는 동안 시트 내용이 손가락을 따라 움직이고, 놓으면 다음 날 내용이 옆에서 들어오는 애니메이션을 보여 줍니다(200ms). `prefers-reduced-motion`이면 애니메이션 없이 바로 바꿉니다.
  - 첫날에서 오른쪽, 마지막 날에서 왼쪽으로 밀면 살짝 늘어났다 돌아오는 반동만 보여 주고 일차는 그대로입니다(순환하지 않음).
  - 일차가 바뀌면 상단 화살표와 같은 동작을 합니다(`selectDay`): 지도 강조, 라벨, 목록이 모두 같이 바뀝니다.
  - "전체 동선" 상태에서 밀면 Day 1(왼쪽으로 민 경우) 또는 마지막 날(오른쪽으로 민 경우)로 들어갑니다.
  - 시트 머리에 현재 위치 표시를 둡니다: `‹ Day 2 · 11/24 ›`와 아래 점 표시(●○○○○, 일수가 8일을 넘으면 "2 / 20" 숫자로 표시).
  - 지도 위에서 손가락으로 미는 것은 지도 이동으로만 동작하고, 일차는 바꾸지 않습니다.
  - 접근성: 기존 ‹ › 버튼은 유지하고, 시트 머리에 `aria-roledescription="carousel"`과 "Day 2 / 5" 안내를 넣습니다.
  - 테스트: 터치 이벤트로 가로·세로·대각선 제스처, 첫날·마지막 날 경계, 전체 동선 상태를 확인합니다.

### I-4. 모바일에서도 화면 밝기(달·해) 버튼을 헤더에 표시 (#4)

- **완료 기준**

  - 테마를 바꾸면 지도 바탕(밝은 거리 지도 ↔ 어두운 지도)도 함께 바뀝니다.

### I-5. 상하이 가이드 "이 코스 그대로 불러오기"가 코스대로 들어가지 않음 [확인]

    - [이 장소 일정에 담기]: 앱으로 이동해 여행과 일차를 고르는 창을 띄웁니다(I-5 확인 창과 같은 컴포넌트).

### J-10. 장거리 구간(고속철) 이동 시간이 몇 시간으로 잘못 나옴 (사용자 실제 여행 계획, 2026-11-25) [P1]
- **현상:** 이번 주 항저우 일정에서 하루 요약 칩이 "예상 이동 약 7시간"으로 표시됩니다. 자싱남역 → 항저우동역(직선 약 72km)을 도심 대중교통 계수로 계산했기 때문입니다. 실제 고속철은 약 25분입니다.
- **원인:** 이동 시간은 직선 거리 × 수단별 계수(도보·대중교통·택시, 447~451행의 기존 제안)로만 계산합니다. 구간마다 이동 수단을 정하는 기능이 없고, 도시 사이 장거리 이동을 구분하지 않습니다.
- **영향:** 도시를 옮기는 날(상하이 → 자싱 → 항저우처럼 이 서비스의 핵심 사용 패턴)마다 하루 이동 시간이 몇 배로 부풀려집니다. 사용자는 일정이 너무 빡빡하다고 오해하거나 숫자를 믿지 않게 됩니다. 앞으로 다른 숫자까지 믿지 않게 되는 게 더 큰 문제입니다.
- **완료 기준**
  1. **구간별 이동 수단 지정:** 장소와 장소 사이의 이동 구간(타임라인 연결선)을 누르면 수단을 고를 수 있습니다: 도보 / 대중교통 / 택시 / 고속철·기차 / 비행기 / 직접 입력(분).
     - 고속철·기차를 고르면 소요 시간(분)과 선택 입력(열차 번호 예: G7xxx, 출발·도착 시각)을 받습니다. 출발·도착 시각을 넣으면 소요 시간은 자동 계산합니다.
     - 지정한 구간에는 수단 아이콘과 시간을 표시합니다(예: 🚄 25분). 하루 요약 칩도 이 값을 씁니다.
  2. **자동 판별 (지정하지 않은 구간):**
     - 직선 거리 30km 이상이면 도심 계수로 계산하지 않습니다.
     - 양쪽 끝이 기차역(이름에 站·駅·역·Station 포함, 또는 장소 분류가 철도역)이면 "고속철일까요?" 칩을 보여 주고, 누르면 고속철 시간 입력 칸을 엽니다.
     - 수단이 정해지지 않은 장거리 구간은 하루 합계에서 빼고, 칩을 "예상 이동 약 1시간 10분 + 장거리 1구간(수단 미정)"처럼 따로 표시합니다. 잘못된 몇 시간짜리 숫자를 보여 주지 않는 것이 핵심입니다.
  3. **항공편 연결:** 이미 등록한 항공편의 출발·도착 공항 사이 구간은 항공편 시간을 그대로 씁니다(P1 항공편 Day 표시와 같은 데이터 사용).
  4. **데이터:** 구간 설정은 `segments[fromPlaceId→toPlaceId] = { mode, minutes, trainNo?, dep?, arr? }`처럼 두 장소 id 쌍을 키로 저장합니다. PART L 공동 편집 문서(Y.Map)에도 같은 구조로 들어가게 L-0 매핑표에 추가합니다.
  5. **번역:** 수단 이름과 칩 문구는 4개 언어로 넣습니다. 열차 번호와 역 이름은 사용자가 입력한 그대로 표시합니다.
- **엣지 케이스**
  - 장소 순서를 바꾸면 기존 구간 쌍이 사라집니다. 설정은 지우지 말고 보관해 두었다가 같은 두 장소가 다시 붙으면 되살립니다. 새로 생긴 구간은 자동 판별로 돌아갑니다.
  - 같은 역이 다른 이름으로 두 번 들어간 경우(嘉兴南站 / 자싱남역)는 거리 0에 가깝습니다. 이동 0분으로 처리하고 경고하지 않습니다.
  - 야간열차나 날짜를 넘기는 구간은 도착 시각이 다음 날이 될 수 있습니다. 하루 합계는 출발한 날에만 넣습니다.
  - 고속철 지정 구간에도 "역까지 이동 + 대기" 여유 시간을 따로 넣을 수 있어야 합니다. 기본값은 0분이고 숨김으로 두며, 사용자가 넣으면 합계에 포함합니다.
  - 보드 보기 좁은 칸(약 320px)에서 수단 아이콘과 시간이 한 줄에 들어가야 합니다(I-6과 같은 기준).

### J-13. 지도 번호 마커 ↔ 일정 리스트 연동 [P1]
- **현상:** "전체 동선"을 누르면 하루 전체가 보입니다. 하지만 번호 마커를 눌러도 그 장소로 확대되지 않고, 리스트에서도 해당 장소가 강조되지 않습니다.
- **완료 기준**
  1. **번호 마커 클릭:** 마커가 활성 상태(크기 확대·색 강조)로 바뀝니다. 그 장소 주변으로 부드럽게 확대합니다(예: zoom 16, 이미 더 확대돼 있으면 유지). 리스트에서 같은 장소 카드를 강조하고, 화면 밖이면 그 위치로 스크롤합니다.
  2. **리스트 카드 클릭(또는 탭):** 반대로 지도에서 해당 마커를 활성화하고 그 위치로 이동합니다. 카드 안의 버튼·입력칸을 누를 때는 동작하지 않습니다.
  3. **"전체 동선":** 활성 상태를 풀고 하루 전체 범위(fitBounds)로 돌아갑니다.
  4. **활성 상태는 한 번에 하나:** 다른 마커를 누르면 이전 활성은 풀립니다. 빈 지도를 누르거나 Esc를 누르면 해제합니다.
  5. **모바일:** 지도 시트가 반쯤 열린 상태에서 마커를 누르면 시트에 해당 장소 카드가 보이도록 스크롤합니다(I-3 시트 스와이프와 충돌 없게).
  6. 숙소 마커도 같은 규칙을 따릅니다.
- **엣지 케이스:** 좌표가 거의 같은 장소 두 개(같은 건물 안)는 마커가 겹칩니다. 확대 후에도 겹치면 살짝 벌려서 둘 다 누를 수 있게 합니다. 좌표가 없는 장소는 리스트에서 눌러도 지도가 움직이지 않고 "위치 정보 없음"을 짧게 안내합니다.

### J-19. 데스크톱 보드: 마우스 드래그로 가로 이동 [P1]

### J-21. 지도 패널: 버튼 하나로 숨기기·보이기 [P1]
- **요청:** 지도를 버튼 하나로 숨겼다 보였다 하고 싶습니다. 사용자가 참고 아이콘으로 사이드 패널 토글 모양(둥근 사각형 안에 세로 막대)을 보냈습니다(`docs/screenshots/2026-11-25-map-toggle-icon-reference.png`).
- **완료 기준**
  - 일정 화면 상단 도구줄의 고정된 자리에 **패널 토글 아이콘 버튼 하나**를 둡니다. 누르면 지도 패널이 숨겨지고, 다시 누르면 나타납니다. 기존에 흩어져 있는 지도 접기·펼치기 컨트롤이 있다면 이 버튼 하나로 합칩니다.
  - 지도를 숨기면 일정 목록이나 보드가 남은 폭을 모두 씁니다. 보드 보기에서는 한 화면에 칸이 더 많이 보입니다.
  - 아이콘은 상태에 따라 바뀝니다(막대 채움 / 비움). `aria-pressed`와 툴팁("지도 숨기기" / "지도 보기")을 4개 언어로 넣습니다.
  - 상태는 `xenotravel:prefs`에 저장해서 새로고침 후에도 유지합니다. 목록 보기와 보드 보기는 각각 따로 기억합니다(보드는 지도 숨김을 더 선호할 수 있음).
  - 전환 애니메이션은 200ms 이하로 짧게 하고, `prefers-reduced-motion`에서는 끕니다. 지도가 다시 보일 때 Leaflet `invalidateSize()`를 호출해 타일이 회색으로 비지 않게 합니다.
  - 단축키 `M`으로도 전환합니다(입력칸에 포커스가 있을 때는 동작하지 않음).
  - 모바일은 지금의 지도 시트(I-3)를 유지합니다. 이 버튼은 데스크톱·태블릿 가로(1024px 이상)에서만 보입니다.

  - 고른 이유:
    - 두 사람이 같은 날 장소를 동시에 끌어서 순서를 바꿔도 데이터가 깨지지 않고 합쳐집니다.
    - 해외에서 인터넷이 끊긴 상태로 수정해도 다시 연결되면 자동으로 합쳐집니다(이 앱의 오프라인 사용 패턴과 맞음).
    - 협업 편집 기능에서 많이 쓰는 방식이라 자료와 호스팅 선택지가 많습니다.
  - 기기 안 저장: `y-indexeddb`로 IndexedDB에 저장합니다. 오프라인에서 열고 수정할 수 있습니다.
- **서버: Supabase 무료 플랜 (1순위)**
  - Supabase가 직접 관리하는 Yjs 연결 라이브러리 `@supabase-labs/y-supabase`를 씁니다. Realtime broadcast로 실시간 동기화하고, `yjs_documents` 테이블에 문서 상태를 저장합니다. 직접 WebSocket 서버를 만들지 않습니다.
  - 무료 플랜 한도(2026-11 기준, 시작 전에 supabase.com/pricing에서 다시 확인): 프로젝트 2개, DB 500MB, 파일 1GB, 전송량 5GB, 월 활성 사용자 5만. 여행 문서 하나는 보통 수십 KB라 초기 사용량으로는 충분합니다.
  - **주의 1. 7일 동안 사용이 없으면 프로젝트가 일시 정지됩니다.** 베타 기간에는 Vercel Cron으로 하루 한 번 가벼운 조회를 보내 막습니다. 실제 사용자가 생기면 Pro($25/월)로 올릴지 판단합니다. 정지된 상태에서도 앱이 깨지지 않게, 연결 실패 시 "지금은 동기화할 수 없어요. 이 기기에는 저장돼 있어요" 상태로 전환합니다(y-indexeddb가 로컬 사본 유지).
  - **주의 2. 국가별 차단 사례가 있습니다.** 2026년 인도 등에서 `*.supabase.co` 도메인이 통신사 단위로 차단된 적이 있고, 중국에서는 지연이나 접속 불안정이 보고돼 있습니다. 대응:
    - 브라우저가 `*.supabase.co`에 직접 붙지 않도록, 처음부터 내 도메인을 거치는 프록시(예: `sync.xenoday.com` 또는 Vercel rewrite)를 둘 수 있게 Supabase URL을 설정값 하나로 분리합니다.
    - L-0에서 중국(VPN 없이), 한국, 일본에서 실제 연결 테스트를 하고 결과를 표로 남깁니다. 중국에서 안 되면 Cloudflare Durable Objects + `y-partyserver` 같은 대안을 같은 표에 비교합니다.
  - 리전: 서울(ap-northeast-2) 또는 도쿄 중 L-0 테스트에서 중국·한국 양쪽 지연이 낮은 쪽을 고릅니다. 고른 리전은 개인정보처리방침의 "국외 이전" 항목에 그대로 적습니다.
  - 보안: 브라우저에는 anon key만 둡니다. 테이블은 RLS(행 수준 보안)를 켜고, 문서 읽기·쓰기는 초대 토큰을 확인하는 RPC/Edge Function을 거쳐서만 허용합니다. service_role 키는 서버 환경변수에만 둡니다.
- **로그인: 가입 없이 초대 링크 방식(MVP)**
  - 초대 링크에 추측할 수 없는 토큰(128비트 이상)을 넣습니다. 링크를 가진 사람이 편집자가 됩니다.
  - 처음 들어올 때 이름(닉네임)만 받습니다.
  - 서버에는 토큰의 해시만 저장하고, 링크 재발급(이전 링크 무효화)을 지원합니다.
  - 정식 계정(이메일 매직링크)은 이후 단계에서 검토합니다.

### L-0. 설계 확정 (코드 작성 전)
- 동기화 서비스 후보 비교표: 비용, 무료 한도, 중국·한국·일본에서의 연결 테스트 결과, 데이터 삭제 방법

- 개인정보처리방침 변경안: 서버에 저장되는 항목, 보관 기간, 삭제 방법, 서버 위치

### L-1. MVP: 초대 링크로 함께 편집
- **켜기:** 여행 ⋯ 메뉴 → [친구와 함께 편집] → 설명 창을 띄웁니다("이 여행이 서버에 저장돼요"). [초대 링크 만들기]를 누르면 링크가 복사되고 카톡 공유가 열립니다.
- **받는 쪽:** 링크를 열면 "○○님이 '상하이 여행'에 초대했어요" 화면과 이름 입력 칸이 나옵니다. [참여하기]를 누르면 내 여행 목록에 추가됩니다.
- **동기화 범위:** 일차와 장소(순서, 시간, 메모), 보관함, 숙소, 항공편, 체크리스트, 여행 이름·날짜·커버를 동기화합니다.
- **가계부:** 지출마다 "낸 사람"을 기록하고, 기존 "동행자 · 정산하기"와 연결합니다. 개인 지출(나만 보기) 표시를 지원합니다.
- **누가 무엇을 했는지**
  - 상단에 지금 보고 있는 사람의 이니셜 동그라미를 표시합니다.
  - 다른 사람의 변경은 짧은 알림으로 보여 줍니다. 예: "민지가 Day 2에 南湖를 추가했어요"
  - 장소 카드에 마지막으로 수정한 사람의 이니셜을 작게 표시합니다.
- **실행 취소:** 내가 한 변경만 되돌립니다(Yjs UndoManager의 origin 구분).
- **연결 상태 표시:** 헤더에 "동기화됨 / 오프라인, 연결되면 합쳐져요 / 동기화 중"을 표시합니다.
- **기존 여행 전환:** 개인 여행을 공동 여행으로 바꿀 때 현재 데이터를 그대로 옮깁니다. 바꾸기 전 자동 백업 파일을 만듭니다.
- **나가기·삭제**
  - 편집자는 [이 여행에서 나가기]로 내 목록에서만 뺍니다.
  - 소유자는 [공동 편집 끄기]로 링크를 무효화합니다(내 기기에는 개인 여행으로 남음). [서버에서 완전히 삭제]도 둡니다.

### L-2. 충돌·예외 처리 기준
- 같은 장소를 동시에 다른 날로 옮기면 마지막으로 반영된 쪽이 이깁니다. 진 쪽에는 "민지가 이 장소를 Day 3으로 옮겼어요" 알림을 보여 줍니다.
- 한 사람이 지운 장소를 다른 사람이 수정하면 삭제가 우선합니다. 수정한 사람에게 [되살리기] 알림을 보여 줍니다.
- 여행 날짜 변경(P0-9 "날짜 기준 유지")은 소유자만 할 수 있습니다. 변경되면 모두에게 안내합니다.
- 오프라인에서 오래(예: 7일) 수정한 뒤 연결되면 "오프라인 중 바뀐 것 n개를 합쳤어요" 요약을 보여 줍니다.
- 기존 `lib/sync.js`(탭 간 병합)는 공동 여행에서는 쓰지 않습니다. Yjs가 탭 간 동기화도 처리합니다.
